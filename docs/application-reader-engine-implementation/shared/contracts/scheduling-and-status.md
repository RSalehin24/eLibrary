# Schedule execution, job projections, and bounded transport

Supplement to [private engine v1](private-engine-v1.md). E01 establishes transport, current authority, job/projection identity and minimum fenced recovery before service cutover. E06 adds production publication; E07 completes update automation and the broader recovery matrix. These guarantees cannot be deferred while a live operation already depends on them.

## Run Now and scheduled workflow

`POST /internal/v1/engine/schedules/{schedule_id}/run/` accepts exactly `{schema_version, operation_id, expected_revision}` with the signed actor and matching Idempotency-Key. Under a schedule lock validate current actor processing/schedule authority and the revision, snapshot its settings, persist an internal `run_schedule` parent and outbox, then return `202 {operation_id, revision, state}`. A disabled schedule can run explicitly if the actor remains authorized; this does not enable it or move its next scheduled occurrence.

The scheduler calls the same admission helper with the schedule's persisted run-as account, `trigger: scheduled` and `scheduled_due_at`. These are internal recorded values, not user-supplied extra fields on a command. Scheduled uniqueness is `(schedule_id, scheduled_due_at)`; manual uniqueness is the actor/operation idempotency key. Parent input records `{schedule_id, schedule_revision, trigger, scheduled_due_at, settings}`; manual due time is null. Its settings are immutable after admission; later edits/disable affect future occurrences, not that running snapshot. Cancelling an already-running snapshot is an explicit control.

1. `discover_source` runs discovery, then optional creation according to process-all/limit. With fetch-all true, use bounded continuations until the complete provider catalog is accounted for. With fetch-all false, `source_max_pages` caps that run's explicit refresh scope; finishing that scope is bounded discovery completion, not a new full-catalog census. A transport/parse failure is different from reaching the configured page bound and prevents dependent creation for that run.
2. `process_catalog` runs creation without implicit discovery and requires a previously complete known catalog revision. `sync_unfinished` probes known unfinished sources and rebuilds changed records only when requested; an incomplete probe never invents a successful sync. After discovery/probing, freeze the actual eligible selection and its revision. Process All requires a known complete catalog universe, preserves previously known records during a bounded refresh and shows the last full-census time separately from recent bounded updates. Before any complete census exists, bounded discovery may create only an explicit confirmed target set; all-catalog processing waits with `catalog_census_required`. Apply unfinished/all/updated scope and rebuild policy then. Positive processing-limit caps post-discovery creation; 0 queues none unless process-all is true. Reject enabled creation-only settings with neither process-all nor a positive limit. Do not claim full source coverage from a bounded run.
3. Create child commands through deterministic UUIDv5 IDs derived from the parent UUID, stage, source ID and frozen revision. Retried parent dispatch cannot create another child. For a target already active, record a joined/already-active outcome with its operation reference rather than another processing operation.
4. Track own-created children separately from joined work and publish per-target outcomes. `queueing_complete` is a stage/count, not terminal book success. Parent remains running/retry-wait/paused as appropriate until required children settle. Parent succeeds only when its configured work succeeds; failed children yield `failed/child_failed`, and a mix remains visible through counts. Source-unavailable children can keep the parent waiting with a next probe; do not fabricate a failed or succeeded book to finish the parent.

A parent pause/cancel stops new child admission immediately and requests the same control on its own active children. It never cancels joined work owned by another run. If any owned child is inside its publication fence, the parent reports Stop requested until that receipt is resolved; the child may succeed, and the parent's cancelled summary retains that outcome. Pause/resume does not restart succeeded children. Scheduler/manual overlap joins the one active source operation, so it cannot publish duplicates. Define these semantics for website bulk controls as well.

## One current job list across services

Keep browser-facing `/api/v1/manage/jobs/` and detail/control route families. Website preparation/delivery jobs stay in the website DB; engine creation/discovery/schedule operations are represented by a website-owned status projection keyed by `(backend, operation_id)`. This projection is an index for display/filtering, not an execution queue. Source/catalog read screens use the bounded engine source APIs and show a recoverable unavailable state when the engine is down.

Engine status transitions commit an outbox event along with their operation update. `POST /internal/v1/website/engine-events/` with service-only scope `website:status` accepts `{schema_version, event_id, operation_id, operation_revision, context_id, kind, state, stage, reason_code, requested_by_id, book_id, source_id, parent_operation_id, counts, created_at, updated_at}`. Every key is present; nullable relationships use null. IDs must match the stored operation identity; unknown kinds/states and malformed counters are rejected. Requested-by/kind/source/parent/created-at are immutable. A source operation's book/context may initially be null; a newer event can bind its book exactly once to the website-owned source/context reservation for that operation/actor. A refreshed context may change only to another snapshot for that same operation/book/source. Reject book rebinding or an unknown/foreign context; batches keep both fields null. Use event ID as Idempotency-Key and no raw job input/source text/credentials in events.

The website inbox atomically stores the receipt and applies only a newer operation revision. An older duplicate is acknowledged without reverting state; a same revision/different payload is an integrity conflict. Event delivery remains allowed after requested-by account revocation so final outcomes do not get stranded; it grants that account no UI access. Web list/detail/control responses still apply the current viewer's permissions. Unknown projected IDs are looked up through an authenticated engine status call before binding, never accepted as a mutable website job.

Merge projections with website job summaries in the website query layer before filtering/counting/pagination, using stable `(created_at, backend, operation_id)` ordering. Do not concatenate two independently paged lists and claim a correct combined total. Query projections can retain small terminal summaries without importing old engine history. Controls dispatch by the registered backend and original revision; an ID collision does not pick a random service.

While active views are open, use the existing bounded UI polling; projections reconcile at least every 60 seconds after a missed event. For bounded administrative reads, operation lists support `updated_after` and `after_id` ordered by `(updated_at, operation_id)`, with overlap safe through operation revisions. This timestamp cursor is not the sole recovery mechanism: outbox delivery scans every unacknowledged event regardless of timestamp/sequence, and reconciliation separately checks every known nonterminal projection by operation ID. Scan source-unknown/recent terminal records in complete overlapping passes; never advance a terminal-change guarantee past an unacknowledged event. A transaction assigned an earlier timestamp but committed late therefore cannot disappear behind a cursor. Store a read cursor only after its complete page commits. Engine downtime exposes `last_confirmed_at` and stale/unavailable status rather than a new success; terminal UI outcomes need a confirmed event/receipt.

The background reconciler uses null assertion actor and the service-only `engine:reconcile` scope on operation list/detail, restricted to the projection fields and stable cursor. User status reads still use `engine:status` with the current viewer. Neither scope permits an operation control, source/body read, artifact generation or account/grant change.

## Authority operations and service-only reconciliation

The website authority endpoint accepts these operation strings only: `discover_source`, `process_source`, `process_catalog`, `sync_unfinished`, `run_schedule`, `control_operation`, `view_source`, `view_operation`, `manage_schedule`, `book_context`, `publish_source`. Discovery/processing/control/schedules/context/publication require active processing-management authority; source inspection additionally honors the existing source-record-view grant. Existing book override mutations require the administrator rule independently. Target book binding/source relationship must match; null is allowed only for non-book/global operations.

Status for an engine operation requires current authorized processing administration, or another explicitly retained object-read rule; a guessed UUID is insufficient. Authority answers use only website-owned accounts/grants/book bindings and timestamps. Cache expiry is at most 120 seconds, but engine protected boundaries refresh decisions and website activation does a current locked check regardless of the cache. A periodic grant expiry can deny authority without a changed counter. Authority lookup cannot recursively request engine status.

Publication events, sealed artifact transfer, projection delivery and reading a recorded receipt use their service-only scopes, binding their immutable operation/context. They do not rely on a revoked user's ability to read status. Activation still validates the persisted original actor; revocation rejects a pending activation while an already activated receipt stays a recorded success. No retry creates or elevates an account/grant to make work succeed.

## Bounded IO and reconciliation

Use existing HTTP/runtime clients with validated configuration. Target defaults: connection timeout 3 seconds; private control/authority/status deadline 15 seconds; source request idle-read timeout 30 seconds and total deadline 60 seconds; artifact idle-read 30 seconds and total deadline 300 seconds; local inference deadline 300 seconds per chunk. Bound source redirects at 3 with host/DNS/scheme revalidation each time. Apply actual streamed byte limits, regardless of Content-Length; an overrun never gets staged as valid. A process heartbeat runs separately from a slow IO/model call.

Admission returns only after the durable inbox/outbox commit; it does not hold the HTTP response open for work completion. Retry private status/receipt reconciliation after 1, 2, 5, 15, then 60 seconds capped, with bounded jitter. Start a new nonce/short-lived assertion for each retry but preserve mutation key and exact body bytes. The assertion is checked on request admission; a long valid transfer is not cut off midstream merely because that assertion expires. Failure to authenticate a retry refreshes service credentials/configuration, never changes its business identity.

An unresponsive inference process can be terminated/restarted at the per-chunk deadline; the old attempt is fenced before another can commit a decision. Validation/ambiguity has the bounded decision-retry policy; transport outages use paced availability retries. If timeout configuration changes, record it with E03 measurements and rerun dependent cancellation/resource checks.

A pending website publication receipt is processed by a website-owned durable consumer with a 15-second heartbeat and 90-second stale lease. It resumes/revalidates after crash, using the same receipt/context and immutable artifacts. Checksum/invalid-manifest/authority/archive/version conflicts produce terminal rejection. Temporary engine/network/disk failures keep it pending with `reason_code`, next retry and `last_confirmed_at`; no new publication event is invented. A genuinely unknown commit outcome remains reconciliable and visible rather than being cleared by an operator's blind retry. Engine watchdogs reclaim the reconciler, not the sealed publication into a second generating attempt.

## Contract regressions

Manual Run Now while disabled; scheduled/manual overlap; bounded discovery before/after a full census; discovery succeeds/creation fails; discovery fails/creation never starts; all-zero/no-op enabled schedule; settings edit during run; parent retry after some children commit; pause/cancel joined versus owned children; child already publishing; null-to-reserved book context followed by rejected rebinding; duplicate/out-of-order projection; same revision/different payload; late transaction behind a read cursor; combined pagination/count across both backends; backend ID collision; unknown/forged service scope; authority recursion prevention; revoked user with terminal receipt; lost projection and cursor-page replay; dead publication consumer; slow streams/model timeout and delayed completion after fencing. Include current bilingual UI status and no duplicate/unauthorized effects.
