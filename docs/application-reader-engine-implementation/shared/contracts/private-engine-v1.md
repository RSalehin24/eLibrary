# Private engine interface v1

**Target interface**, implemented in E01/E06/E07. No endpoint below is claimed to exist today. This contract is deliberately narrow: use existing Python/Django validation, transactions, signing primitives, and HTTP tooling. Do not add a service framework or distributed transaction dependency.

## Transport and request identity

Private routes are available only on internal listeners and denied by the public proxy. Use authenticated TLS between hosts; loopback/private-container transport is acceptable in the isolated local stack. An allowlisted service origin comes from configuration. Neither service follows arbitrary artifact URLs supplied in a payload.

Each request carries an `Authorization: Library-Service <payload>.<signature>` assertion. The payload is base64url UTF-8 JSON with exactly `v`, `key_id`, `issuer`, `audience`, `actor_id`, `scope`, `issued_at`, `expires_at`, `nonce`, `method`, `path`, `idempotency_key`, and `body_sha256`. Sign the encoded payload with HMAC-SHA256 using a service-specific configured secret and compare signatures in constant time. Require version 1, a recognized key, matching audience/method/path/body/idempotency header, a single allowed scope, lifetime at most 120 seconds, and clock skew at most 30 seconds. Assertion times are integer UTC epoch seconds; nonce is a random UUID. The signed `path` includes the exact encoded request path and query string, binding list filters as well. Non-mutations use null `idempotency_key`; empty bodies hash as empty bytes. Reject malformed/extra/duplicate JSON fields, oversized assertions (over 4096 bytes), and unknown issuers. Never log the assertion or secret.

Website↔engine and engine↔inference use different secrets/listeners. The signed envelope in this document applies to the enumerated `/internal/v1/` endpoints; do not assume llama.cpp accepts this custom scheme. E03 records the pinned runtime's supported authentication on its private loopback/listener before use. Keep secrets outside the repository; rotate internal signing keys by key ID with an overlap no longer than the assertion lifetime plus skew. No browser receives this credential. Assertions authenticate a service call, not unlimited durable user authority.

For mutations, `Idempotency-Key` is a UUID and the JSON includes `schema_version: 1`. Persist issuer/actor/key/method/path/body hash and the result in the receiving inbox transaction. Same key and identical request returns the same receipt; a different request is `409 idempotency_conflict`. A reused nonce with different signed bytes is rejected; changing an unsigned header cannot turn a captured request into another mutation. Exact retries can retrieve the recorded response after fresh service authentication and the applicable user or service-scope checks. Store replay records for at least 24 hours after expiry; keep compact terminal mutation receipts through the operation/build lifecycle so delayed retries cannot duplicate work.

User-originated command/control/schedule/source/status/context calls carry the current account's decimal-string `actor_id` and require current target authority. Durable outbox status events, sealed artifact transfer and publication receipt reconciliation carry null assertion actor and use narrowly allowed service scopes; their operation/context records preserve the original requested-by account. This permits a committed receipt to be reconciled after that account is revoked, without permitting a new activation: website activation always rechecks the stored origin actor under locks. A user cannot obtain service-only scopes. Website authority decisions read website-owned account/grant/binding state only and never call the engine recursively.

Use UUIDs for engine-owned IDs, website account IDs as opaque decimal strings, UTC ISO-8601 timestamps, lowercase hex SHA-256, nonnegative integer revisions, bounded enum strings, and UTF-8 original-language text. Reject unknown fields and unsupported schema versions. JSON control requests/responses cap at 1 MiB; large canonical documents, evidence, resource manifests and sealed build manifests use bounded streamed artifact transfer instead of embedding their contents in commands/status. The sealed build-manifest response is the explicit exception described below, not subject to the smaller control-envelope limit. Reuse `{code, detail, field_errors}` for errors. Private authentication failure is `401`, scope denial `403`, hidden/missing object `404`, validation `400`, stale revision/version/idempotency mismatch `409`, and temporary transport/resource failure `503` with retry timing.

## Endpoint inventory

All paths below are complete internal paths. IDs in braces are validated opaque identifiers, never filesystem paths.

| Owner / method / path | Required scope | Request and response |
| --- | --- | --- |
| Engine `POST /internal/v1/engine/commands/` | `engine:command` | Accept the command envelope below; return `202 {operation_id, revision, state, status_path}` only after command and outbox commit. Duplicate admission returns the original operation. |
| Engine `GET /internal/v1/engine/operations/{operation_id}/` | `engine:status` or service-only `engine:reconcile` | Return the status envelope below; no raw book text, credentials, or absolute storage paths. Reconcile scope returns projection fields only. |
| Engine `GET /internal/v1/engine/operations/` | `engine:status` or service-only `engine:reconcile` | Bounded page/limit and whitelisted kind/state/source/schedule filters; return status summaries and pagination. Reconcile scope is limited to projection/cursor data. |
| Engine `GET /internal/v1/engine/sources/` | `engine:status` | Bounded source list with search, completion/collection state, all/updated scope and frozen catalog revision; return source summaries and pagination. |
| Engine `GET /internal/v1/engine/sources/{source_id}/` | `engine:status` | Return the source envelope below and bounded structure/change summaries; no raw snapshot body or provider credentials. |
| Engine `POST /internal/v1/engine/operations/{operation_id}/controls/` | `engine:control` | `{schema_version, action, expected_revision}`; action is pause/resume/cancel/retry. Return updated status; invalid transitions are `409`. |
| Engine `GET /internal/v1/engine/schedules/` | `engine:status` | Bounded page/limit query; return `{entries, pagination:{page,limit,total_count}}`. |
| Engine `GET /internal/v1/engine/schedules/{schedule_id}/` | `engine:status` | Return the complete current schedule envelope. |
| Engine `GET /internal/v1/engine/schedules/{schedule_id}/runs/` | `engine:status` | Bounded operation summaries with due time, missed count, current state and partial target counts. |
| Engine `POST /internal/v1/engine/schedules/` | `engine:schedule` | Create the schedule envelope below, returning `201 {schedule_id, revision, next_run_at}`. |
| Engine `PUT /internal/v1/engine/schedules/{schedule_id}/` | `engine:schedule` | Full schedule values plus `expected_revision`; return the committed schedule. Disable instead of deleting execution history for a current schedule. |
| Engine `POST /internal/v1/engine/schedules/{schedule_id}/run/` | `engine:schedule` | Revision-checked Run Now; return durable parent operation. Exact request/child/scheduler semantics are in [scheduling and status](scheduling-and-status.md). |
| Engine `GET /internal/v1/engine/builds/{build_id}/` | `engine:artifact` | Return the sealed build manifest below only for a verified build. |
| Engine `GET /internal/v1/engine/builds/{build_id}/artifacts/{artifact_id}/` | `engine:artifact` | Stream exact artifact bytes with declared length/checksum/media type. Apply size limits before allocation and hash while streaming. |
| Website `POST /internal/v1/website/authority/` | `website:authority` | `{schema_version, actor_id, operation, book_id, source_id}` (nullable targets); return `{allowed, authority_revision, catalog_revision, expires_at}`. Decision expires after at most 120 seconds. |
| Website `POST /internal/v1/website/book-contexts/` | `website:context` | Reserve/resolve one source book and return immutable current metadata/override context, as defined in [publication lifecycle](publication-context-and-lifecycle.md). |
| Website `GET /internal/v1/website/books/{book_id}/covers/{cover_revision}/` | `website:context` | Stream the context's authorized cover revision with bounded length/hash. |
| Website `POST /internal/v1/website/engine-events/` | `website:status` | Idempotent monotonic operation projections; exact event/reconciliation rules are in [scheduling and status](scheduling-and-status.md). |
| Website `POST /internal/v1/website/publications/` | `website:publish` | `{schema_version, event_id, context_id, operation_id, build_id, manifest_sha256, book_id, expected_catalog_revision, authority_revision}`; return `202 {receipt_id, state}` after durable intake. |
| Website `GET /internal/v1/website/publications/{receipt_id}/` | `website:publish` | Return `{receipt_id, event_id, state, book_id, build_id, catalog_revision, reason_code}`. State is pending/activated/rejected; catalog revision is null until activation. |

The website's browser-facing source/job/schedule endpoints retain their current route families and enforce session/CSRF/grants before using these private endpoints. Their API models are projections of these results, not new competing queues or schedule stores. Engine status reads are paginated at default 50, cap 100, with validated positive pages and stable ID tie-breaking. User calls bind assertion actor to request actor and require current target authority. Service-only scopes have the narrower endpoint/field restrictions above; their projections/receipts confer no browser permission. Static scoped assertions never bypass user checks on a user endpoint.

## Command, status, and schedule payloads

Command fields: `schema_version`, `operation_id`, `kind`, `actor_id`, `authority_revision`, `source_id`, `book_id`, `expected_catalog_revision`, `input`, `parent_operation_id`. Nullable targets must match kind. Kinds are `discover_source`, `process_source`, `process_catalog`, `sync_unfinished`; scheduler/Run Now also creates an internal `run_schedule` parent through the schedule-run route/helper, never through arbitrary caller-supplied settings. `input` is a per-kind whitelist below. Never accept executable code, provider credentials, or arbitrary artifact destinations.

| Kind | Exact allowed `input` fields | Target rules |
| --- | --- | --- |
| `discover_source` | `provider_id`, `configuration_revision`, `catalog_revision`, `source_max_pages`, `fetch_all` | Provider must match configuration; catalog revision is nullable for initial discovery; source/book targets are null. |
| `process_source` | `source_revision`, `regeneration_intent` (initial/rebuild/metadata_refresh) | Source target required; existing linked book target/revision supplied when present. Metadata refresh preserves verified body evidence. |
| `process_catalog` | `catalog_revision`, `source_ids`, `scope`, `processing_limit`, `process_all`, `rebuild_updated` | Exactly one of explicit IDs or scope; source/book targets null. Scope is `{query, catalog_scope, updated_only}` using normalized safe filters. |
| `sync_unfinished` | `catalog_revision`, `scope` (all/updated), `rebuild_updated` | Source/book targets null; target source set freezes at command admission. |

Every listed key is present; unused nullable keys use null, not an undocumented alternate shape. Limits/booleans use the schedule bounds/defaults below. Scope query is at most 255 characters, catalog scope is all/unfinished and updated-only is boolean; no raw SQL/filter expression is accepted. Provider ID/configuration revision come from the configured provider record. Actor IDs and signed assertion actors must match. Source/catalog/authority revisions are nonnegative integers; a supplied stale revision conflicts before admission.

Bulk selection is either explicit source IDs (at most 100 per request) or a frozen all-matching scope referencing a catalog revision. The engine records the eligible target set at admission and returns per-target outcomes through parent status. A scope change after confirmation does not silently expand the run. The processing-limit default 0 is used for a schedule's optional post-discovery creation phase; direct Process All requires `process_all: true`. Explicit selected-source commands process that explicit set regardless of an optional schedule limit. [Scheduling and status](scheduling-and-status.md) defines Run Now and parent/child behavior without an undeclared occurrence field.

Status fields: `schema_version`, `operation_id`, `kind`, `revision`, `state`, `stage`, `reason_code`, `available_at`, `requested_action`, `generation`, `attempt_number`, `counts`, `children`, `publication_receipt_id`, `updated_at`. Counts use nonnegative total/accepted/running/succeeded/failed/skipped values only when measurable; queue position is an estimate with measurement time, not a guarantee. Children are bounded summaries with a next-page reference. `requested_action` is empty/pause/cancel. States and transitions are defined in [data and state](data-and-state.md).

Source fields: `schema_version`, `source_id`, `source_url`, `title`, `catalog_revision`, `source_revision`, `book_id`, `source_incomplete`, `collection_state`, `understanding_state`, `reason_code`, `last_successful_sync_at`, `last_probe_at`, `last_probe_outcome`, `changes`, `active_operation_id`, `active_build_id`. Source URL is sanitized public identity, not a credential-bearing request URL. Collection state is uncollected/collecting/complete/unavailable/failed; understanding classifications are defined in E02 and null until audited. Changes contain body/structure/credits/cover/completion booleans and bounded changed-part labels. Summary lists omit large hierarchy/evidence values; detail bounds section depth/size under the existing document limits.

Schedule fields: `schema_version`, `schedule_id`, `actor_id`, `kind`, `scope`, `enabled`, `first_run_at`, `time_zone`, `frequency`, `revision`, `next_run_at`. `time_zone` is `Asia/Dhaka`; `first_run_at` is an unambiguous instant. Retain the existing daily, weekly, biweekly, monthly, bimonthly, quarterly, four-monthly, and half-yearly choices; use their existing enum values from `CatalogAutomationFrequency`. Reject unsupported frequencies. Scope uses the same frozen-selection rules. Revision increments after a schedule edit; automatic occurrence advancement does not replay an old occurrence. `next_run_at` is null when disabled. Reset restores every initial form value, including scope, time, enabled state, and frequency. Read history through operation status, not a second execution store.

Schedule settings additionally retain `name` (1–150 characters), `source_max_pages` (1–200, default 20), `processing_limit` (0–100, default 0), `catalog_scope` (all/unfinished), and booleans `rebuild_updated`, `fetch_all`, `process_all` (default false). Fetch All collects the complete eligible catalog through bounded continuations. Process All selects the complete eligible scope; otherwise a positive processing limit caps selection and 0 queues no creation. Persist these values in the scheduled command input. A schedule stores a scope definition; each occurrence freezes its then-current catalog revision/eligible target set at admission, rather than reusing an obsolete target snapshot forever.

Schedule `kind` is one of `discover_source`, `process_catalog`, `sync_unfinished`; single-source processing uses explicit commands rather than an undocumented schedule scope. The [scheduling contract](scheduling-and-status.md) defines which phases run for each kind and how bounded discovery differs from a full provider census. Default new schedules use `discover_source`, daily, the next 02:00 Dhaka slot and disabled state. Validate kind/settings consistency before saving an enabled schedule.

## Sealed build manifest

Required fields are `schema_version`, `build_id`, `context_id`, `book_id`, `operation_id`, `source_id`, `source_revision`, `document_schema_version`, `extractor_version`, `generator_version`, `verifier_version`, `preparation_version`, `metadata`, `provenance`, `artifacts`, `verification`, and `created_at`. Context/book/source/operation values must match the website reservation and publication event. Uploaded books use the equivalent website preparation manifest without fabricated source evidence.

`metadata` contains whitelisted title/language/edition/summary, contributors with stable entity IDs, role and source evidence, categories, series with identity/sequence, and cover identity. Entity IDs bind supported identity, not normalized display names. It cannot set account IDs, grants, published state, or an administrator override. `provenance` contains source hashes, evidence-artifact ID/checksum, and decision-version keys. `verification` references a source-derived report with coverage/order/entity/structure checks and a verified verdict; an extractor's boolean alone is insufficient.

Each artifact has `artifact_id`, `kind` (html/epub/cover/reader_resources/evidence/verification), normalized relative `name`, `media_type`, `byte_length`, and `sha256`. Require HTML, EPUB, reader resources, evidence, and verification; cover is optional with a UI fallback. Reader resources include a validated manifest and confined resources with individual hashes. Reject duplicates, absolute/traversal paths, unsupported preparation versions, missing required kinds, unexpected files, and size/checksum mismatches. Enforce the existing EPUB/source resource limits plus the measured generation disk budget; no unbounded decompression or in-memory transfer.

Store the sealed build manifest once as UTF-8 JSON with sorted object keys, `ensure_ascii=False`, compact separators, and no NaN/infinity/duplicate keys. Its hash is over those stored bytes; GET returns those exact bytes, with no reserialization or injected self-checksum. Its streamed size cap is the existing 64 MiB document limit. Exceeding a limit is a typed preparation failure, never an implicit truncated manifest. Source/evidence text remains in referenced artifacts, not an unbounded top-level metadata field.

`reader_resources` is an `application/zip` artifact containing `reader-manifest.json` plus exactly its declared sanitized resources at confined relative paths. Reuse approved ZIP/safe-path parsing. Resource data retains the protected-reader limits of 256 MiB expanded, 32 MiB per resource and at most 10,000 resources; reserve one additional manifest entry up to 32 MiB. The transport bundle therefore permits 10,001 entries, 288 MiB expanded and 160 MiB compressed, with the same 100:1 ratio bound. These transport allowances do not enlarge the permitted EPUB or individual reading resources. Count all actual bytes in disk preflight. The manifest binds preparation version, source EPUB checksum, ordered chapters/navigation and per-resource media type/length/SHA-256. Reject nested archives, links/special entries, undeclared/duplicate paths and any mismatched bytes. The website validates this bundle against its preparation policy or regenerates it from the transferred EPUB under the same policy before activation. The 1 MiB control limit never makes an otherwise permitted large resource manifest impossible to transfer.

## Publication transaction and lost replies

1. Engine seals verified artifacts, checks stop/authority/revision, and commits publication outbox event plus its `publishing` fence in one transaction, then sends its stable event ID. A later pause/cancel is rejected as publication in progress; an earlier acknowledged stop prevents the event. It never updates website tables.
2. Website inbox deduplicates the event and records pending receipt. It fetches from the configured engine origin into website-owned staging; validates manifests, hashes, EPUB safety, and reader preparation policy before activation.
3. Website locks the book/publication and current actor/grant state, rechecks authority, expected catalog revision, archive state, and candidate identity. No long file download occurs while holding this transaction.
4. Website atomically switches every active file/reader pointer and accepted metadata in one DB commit. A file rename alone is not activation. Write activated receipt in that same transaction. An incomplete candidate never becomes visible.
5. Engine reconciles receipt, then marks source processing succeeded. After a lost response it polls/retries the same event; it never creates another book to resolve uncertainty. Rejected receipts preserve the reason and do not count as preparation success.

If metadata changed during generation, return a revision conflict. Rebase only automatically extracted fields whose provenance has not been overridden by an admin, then reseal/reverify the candidate. Never overwrite an admin cover/name/credit choice or restore an archived book. A source revision change invalidates only affected downstream stages, with new hashes and generation fencing. See [pipeline](../../engine/pipeline/structure-entities-and-publication.md) and [operations](../../engine/operations/jobs-updates-and-recovery.md).

Identity reservation, metadata context, override precedence, crash-safe file activation and reference-checked cleanup are required parts of the [publication lifecycle](publication-context-and-lifecycle.md). Do not infer those behaviors from a nullable book ID or an extractor's metadata alone.
