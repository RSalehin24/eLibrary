# Requirements - Platform (PLT)

Status: DRAFT

Line format: `REQ-ID · priority · inv: <invariants> · verify: <methods> · statement`

- **REQ-PLT-001** · MUST · inv: INV-PLT-001 · verify: e2e, review · The whole system is built, run and deployed with Docker Compose, one container per component (caddy, web, gateway, identity, catalog, reader, ingestion-api, ingestion-worker, notify, postgres); the same images run in development, CI and production; only caddy publishes host ports; every container has a memory limit and a restart policy (answers X1-082, X1-087).
- **REQ-PLT-002** · MUST · inv: INV-PLT-002 · verify: e2e, review · Each service has its own database and role in the one PostgreSQL container and reaches only its own; no service reads another service's tables or volume; data moves by internal HTTP (streaming for files) and by events.
- **REQ-PLT-003** · MUST · inv: INV-PLT-003 · verify: e2e, unit · A service starts only if its configuration validates (read once at startup, never at import), its database schema version matches the binary, peer contract versions are compatible, secret files are 0400 and readable, and every route declares its scope; otherwise it exits with a typed startup error (answers X1-109).
- **REQ-PLT-004** · MUST · inv: INV-PLT-004 · verify: e2e · Every service exposes liveness and readiness endpoints on its internal port (readiness checks its database and required peers), separate from any application route (answers X1-085).
- **REQ-PLT-005** · MUST · inv: INV-PLT-005 · verify: type, e2e · Every cross-service call and event uses types generated from the Rust contract crates; the web client types are generated from the same contracts; breaking changes need a version bump and a passing compatibility test.
- **REQ-PLT-006** · MUST · inv: INV-PLT-006 · verify: prop · Every mutating endpoint is idempotent (natural key or `Idempotency-Key`); replay returns the original result.
- **REQ-PLT-007** · MUST · inv: INV-PLT-007 · verify: fuzz, unit, static · No panic is reachable from request handling: `unwrap`, `expect` and indexing are denied by lint outside tests; every parser (EPUB, HTML, multipart, tokens) is fuzzed (answers X1-064).
- **REQ-PLT-008** · MUST · inv: INV-PLT-008 · verify: prop, e2e · Every queue, list, page size, body, timeout, retry, bulk id list and concurrency has an explicit documented bound; unbounded loops over remote systems carry a page limit and a cancel check (answers X1-018, X1-068, X1-076).
- **REQ-PLT-009** · MUST · inv: INV-PLT-009 · verify: db, e2e · Security- and admin-relevant actions of every service (at least: authentication events, grants, role changes, publish, unpublish, delete, operator actions, book opens and downloads; D-40) append to its audit log that no service role can update or delete; each row has actor, subject, action, request id and time; retention is 1 year (D-30) (answers X1-084).
- **REQ-PLT-010** · MUST · inv: INV-PLT-010 · verify: model, prop · State change and event publication happen in one transaction (events outbox table per producer, `GET /internal/events?after=<cursor>`); consumers keep a cursor, are idempotent and tolerate duplicates and restarts; no event is lost or applied twice.
- **REQ-PLT-011** · MUST · inv: INV-PLT-011 · verify: type, unit · Time is injected through a `Clock` trait; all stored times are UTC; the UI displays in the viewer's zone (default Asia/Dhaka).
- **REQ-PLT-012** · MUST · inv: INV-PLT-012 · verify: type, review · Code obeys the owner's size and shape rules: functions about 20 lines (cap 30), at most 3 parameters (group inputs in a struct), at most 2 nesting levels, no boolean flag parameters, no magic numbers, no `exec`-style composition of modules; thresholds are lint-enforced where possible and checked in review otherwise (answers X1-105).
- **REQ-PLT-013** · MUST · inv: INV-PLT-013 · verify: review · No dependency (crate, npm package, tool or system package) is added without the owner's recorded approval; the standard library is preferred; the approved register matches the lockfile.
- **REQ-PLT-014** · MUST · inv: INV-PLT-014 · verify: review · Lints, tests and types are never weakened; waivers are dated entries with an expiry in the waiver register.
- **REQ-PLT-015** · MUST · inv: INV-PLT-015 · verify: drill, e2e · Backups are automated: monthly (D-33) `pg_dump` per database plus a file-volume backup, copied off the host, with retention; a restore drill (databases and volumes) is scripted and passes quarterly within the recovery targets in the non-functional requirements (answers X1-080).
- **REQ-PLT-016** · MUST · inv: INV-PLT-016 · verify: review, e2e, static · Every secret in the inventory of [secrets and keys](../10-security/secrets-and-keys.md) is read from a read-only file outside images and the repository (never from an environment variable), never printed on deploy or in logs, and rotatable without a rebuild: per-service database passwords, per-service internal token keys, the identity session and TOTP encryption key, SMTP credentials, the source-site cookie, the backup encryption key (offline custody, never on the backup target), the offsite storage credential, and the TLS certificates held by `caddy` (managed automatically, expiry alerted). (answers X1-002, X1-013, X1-015)
- **REQ-PLT-017** · MUST · inv: INV-PLT-017 · verify: review, e2e · No work runs inside an HTTP request that belongs to a background pipeline: if queueing fails the request fails and nothing runs inline; background work uses the PostgreSQL job queue (claimed with `FOR UPDATE SKIP LOCKED`, leases, heartbeat); no test hook or backdoor exists in production builds (answers X1-005, X1-065, X1-067).
- **REQ-PLT-018** · MUST · inv: INV-PLT-018 · verify: type, unit · Errors are typed with a stable code and a class (`retryable` or `permanent`); every service returns the same JSON error envelope with the request id; retry decisions use the class, never the message text.
- **REQ-PLT-019** · MUST · inv: INV-PLT-019 · verify: e2e, metric · Logs are structured and carry request id, service name and version; every service exports RED metrics plus domain metrics (queue depth, outbox lag, job age); alerts exist for health, backup age, outbox lag and certificate expiry (answers X1-085).
- **REQ-PLT-020** · MUST · inv: INV-PLT-020 · verify: type, e2e · Service-to-service calls carry an internal service token (audience, short lifetime, minimal scope, issued from a secret file); a request without a valid token on an internal route is rejected; the job queue and event endpoints are not reachable from the edge (answers X1-065).
- **REQ-PLT-021** · MUST · inv: INV-PLT-021 · verify: db, e2e · Retention jobs, bounded per run, delete expired sessions, tickets, outbox rows, scrape pages older than 30 days and audit rows older than 1 year (D-30) (answers X1-088).
- **REQ-PLT-022** · MUST · inv: INV-PLT-022 · verify: drill, e2e · A release restarts one service at a time with a health check and an automatic rollback to the previous image; the stack is never taken down and rebuilt as a whole; migrations are backward compatible for one release (answers X1-081).
- **REQ-PLT-023** · MUST · inv: INV-PLT-023 · verify: db, review · State has one source of truth: enums are database enums or CHECK constraints, uniqueness and foreign keys are database constraints, and there is no dual-written or trigger-mirrored status column (answers X1-030, X1-034).
