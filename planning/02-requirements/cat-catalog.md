# Requirements - Catalog (CAT)

Status: DRAFT · Service: [catalog](../05-services/catalog/README.md)

Scope (D-31, D-29, D-32): the catalog service owns books, versions, metadata, contributors, series, categories, publication state, Postgres full-text search, public browse and preview, shelves, saved filters, streamed CSV export and the EPUB/cover files. It absorbs the former discovery (DSC) and content-custody (CON) requirements. Physical-book inventory stays deferred (D-01). Nothing is migrated from the old app (D-32). Duplicate decisions at intake belong to [ingestion](ing-ingestion.md); reading copies belong to [reader](rdr-reader.md).

- **REQ-CAT-001** · MUST · inv: INV-CAT-001 · verify: type, model · A book version is born `published` and later moves only to `archived` (with `archived_reason` `superseded` or `unpublished`); a restore returns an archived version to `published`; deletion is a separate soft-delete flag. No `draft`, `in_review` or rejection state exists (D-49, D-56). A version is created only through ingestion's publish call with gate-passing artifacts, in one transaction (or by the `manage_catalog` restore action); edit, unpublish and delete are manual actions that need `manage_catalog`, not `operate` (D-45). A failed build never reaches catalog and never creates a visible version. (kept from v1, changed by D-49 and D-56)
- **REQ-CAT-002** · MUST · inv: INV-CAT-002 · verify: model, prop, e2e · Reader-facing queries (browse, search, detail, files, shelf, Kindle) are scoped to published, non-deleted versions by construction; operator views are a separate surface that needs `manage_catalog`, and the reader view never carries source URLs. (answers X1-009)
- **REQ-CAT-003** · MUST · inv: INV-CAT-003 · verify: db, prop · A soft-deleted (tombstoned) book is invisible to every read path through one shared repository filter, emits `book.unpublished`, and its files, shelf entries and Kindle requests stop resolving. (answers X1-010)
- **REQ-CAT-004** · MUST · inv: INV-CAT-004 · verify: db, unit · A published book has at least one credit with role writer, translator, editor or compiler (compilers count as editors for this rule). (kept from v1)
- **REQ-CAT-005** · MUST · inv: INV-CAT-005 · verify: db, prop · Each book has an immutable UUID and a unique slug; a renamed slug keeps the old one as a permanent redirect. There are no structured catalog codes (D-36); a book is identified only by UUID and slug. (answers X1-036, X1-063)
- **REQ-CAT-006** · MUST · inv: INV-CAT-006 · verify: db, prop, e2e · Metadata edits are commands through the state machine with optimistic concurrency (stale revision rejected, never merged), full metadata version history, and one source per field. Source-owned and operator-owned fields are separate; a re-import never overwrites an operator edit. A price or count of 0 is distinct from null. (answers X1-026, X1-037, X1-040)
- **REQ-CAT-007** · MUST · inv: INV-CAT-007 · verify: db, prop · Contributors reference agents by id; names are never an identity key. Agents have aliases; merge and split are audited, reversible and re-point credits atomically. A contributor facet matches a (role, name) pair on one credit row. (answers X1-059; kept from v1)
- **REQ-CAT-008** · MUST · inv: INV-CAT-008 · verify: prop, e2e · Series (ordered), categories and each contributor role (writer, translator, editor, compiler) and publisher have browse pages whose counts equal the displayed result set.
- **REQ-CAT-009** · MUST · inv: INV-CAT-009 · verify: prop, e2e · Anyone, signed in or not, can search published books by title, writer, translator, editor, publisher, series, category with PostgreSQL full-text search; results are ranked and contain only published books.
- **REQ-CAT-010** · MUST · inv: INV-CAT-010 · verify: prop, unit · Query and index text pass one Unicode normalization (NFC, digit folding, ZWJ/ZWNJ policy, Bengali spelling-variant folding) that is idempotent and versioned; the query and the index always use the same version.
- **REQ-CAT-011** · SHOULD · inv: INV-CAT-011 · verify: prop, review · Latin-script queries ("humayun ahmed") match Bengali names through the alias table, and vice versa. (kept from v1)
- **REQ-CAT-012** · MUST · inv: INV-CAT-012 · verify: type, model · The public search index and preview endpoint are built only from a `PublicDocument` type (metadata, cover, summary; no preview text, D-34); full text of non-preview sections and any user-private data (shelves, notes, requests) never enter the shared index. (answers X1-019)
- **REQ-CAT-013** · MUST · inv: INV-CAT-013 · verify: prop, drill · The full-text index is derived from the book tables; a full rebuild yields the same result sets as incremental maintenance, and an update is searchable within 30 s at p99.
- **REQ-CAT-014** · SHOULD · inv: INV-CAT-014 · verify: unit, prop · Alphabetical sorting uses Bengali (CLDR `bn`) collation with a total, stable order. (kept from v1)
- **REQ-CAT-015** · MUST · inv: INV-CAT-015 · verify: prop · Facets combine as AND across facets and OR within a facet; facet counts equal result counts for the same filter and snapshot.
- **REQ-CAT-016** · MUST · inv: INV-CAT-016 · verify: prop, e2e · Every list uses keyset pagination with one response envelope; under a fixed snapshot token a page never repeats or skips a result, and page size and result window are bounded. (answers X1-063, X1-076)
- **REQ-CAT-017** · MUST · inv: INV-CAT-017 · verify: fuzz, e2e · Anonymous search and browse are rate limited at the gateway and bounded in query length and result window; the endpoints expose only public data.
- **REQ-CAT-018** · SHOULD · inv: INV-CAT-018 · verify: prop, review · A versioned judged query set (initial target of at least 300 queries, MRR@10 at least 0.85, recall@20 at least 0.95) gates changes to the analyzer or normalization. (changed from MUST at D-29 scale; owner may restore)
- **REQ-CAT-019** · MUST · inv: INV-CAT-019 · verify: type, e2e · Preview needs a signed-in session and the `preview` scope, separate from `read` (D-34, D-41); it is cover, metadata, summary, TOC and the first 3,000 characters of the first chapter (configurable per book, 0 allowed, D-05), built by ingestion at build time; catalog serves only the stored `PreviewArtifact`, never the full document, and marks preview text `noindex` (D-09).
- **REQ-CAT-020** · MUST · inv: INV-CAT-020 · verify: type, db, e2e · EPUB and cover files live only on the catalog volume as write-once, sha256-addressed assets; neither Caddy nor the gateway serves them; catalog streams a file only after its own scope and state check. (answers X1-011)
- **REQ-CAT-021** · MUST · inv: INV-CAT-021 · verify: db, model · A version and its assets are immutable. Publishing is an atomic switch of the current version, so readers see the old or the new version, never a mix; reprocessing creates a new version and never edits a published one; the previous version's files are kept until the next version is published. (answers X1-027, X1-032)
- **REQ-CAT-022** · MUST · inv: INV-CAT-022 · verify: model, db · `POST /internal/books/{id}/versions` is idempotent on the build identity (a retry after a crash creates no second version), accepts the artifacts atomically, and, in the same transaction, publishes the version (no approval step, D-49); it accepts only artifacts that ingestion marks as having passed every gate and re-verifies the hashes and the credit rule. (answers X1-028)
- **REQ-CAT-023** · MUST · inv: INV-CAT-023 · verify: type, e2e · EPUB download is served only against the `download` scope for a published version, as a stream with correct byte ranges.
- **REQ-CAT-024** · MUST · inv: INV-CAT-024 · verify: model, prop · State changes write `book.published`, `book.unpublished` and `book.version_changed` to an events outbox in the same transaction and expose `GET /internal/events?after=<cursor>`; consumers (reader, ingestion) are idempotent. (kept from v1, changed)
- **REQ-CAT-025** · MUST · inv: INV-CAT-025 · verify: db, e2e · "My Books" is a shelf: (user, book) is unique, adding twice is idempotent, and a shelf entry never grants any access. Mutations need `browse`, and a signed-in session. (answers X1-001)
- **REQ-CAT-026** · SHOULD · inv: INV-CAT-026 · verify: prop · Saved filters round-trip: applying a saved filter reproduces the identical query; a duplicate save returns a typed 409, not a 500. (answers X1-038)
- **REQ-CAT-027** · SHOULD · inv: INV-CAT-027 · verify: prop, e2e · An authorized operator can export the current filtered list as streamed CSV (no XLSX or PDF, D-30); rows equal the list rows for the same filter and snapshot, cells beginning with `=`, `+`, `-`, `@` are neutralized, control characters are quoted, and a row cap bounds the size. (answers X1-022, X1-102)
- **REQ-CAT-028** · MUST · inv: INV-CAT-028 · verify: unit, review · Cover images are accepted only after validation by bytes (type, size, checksum) and fetched only from allow-listed hosts; without a source image a generated cover shows the title and author with correct Bengali shaping and no missing glyphs. (answers X1-021)
- **REQ-CAT-029** · MUST · inv: INV-CAT-029 · verify: model, e2e · A Kindle send requires the `kindle` scope and a published version, is capped in size, rate limited per user, and becomes a `kindle.requested` event; notify reports delivery status (address, status, error) back, shown on the book's Files tab. (answers X1-042, X1-075)
- **REQ-CAT-030** · MUST · inv: INV-CAT-030 · verify: unit, e2e · Uniqueness and state conflicts map to typed 409/422 errors with a stable code and field path; missing or deleted resources are 404, never 500. (answers X1-038)
- **REQ-CAT-031** · MUST · inv: INV-CAT-031 · verify: db, e2e · Every catalog state change (publish, edit, unpublish, merge, delete, file replace, export, EPUB download, Kindle request) appends an audit event with the actor. (answers X1-084)
- **REQ-CAT-032** · MUST · inv: INV-CAT-032 · verify: prop, e2e · GET handlers are side-effect free: a missing or unreadable file returns an error and never marks a version failed or queues work. (answers X1-032)
- **REQ-CAT-033** · MUST · inv: INV-CAT-033 · verify: db, prop, type, e2e · Saved filters are kept (D-43) and owned by catalog per user: each belongs to one user and is visible only to them, the count per user is bounded by a configured limit (excess is a typed error), and the parameters are stored as JSON that is validated against a schema on save and on apply.
- **REQ-CAT-034** · MUST · inv: INV-CAT-034 · verify: db, e2e · A signed-in user can download their own catalog data as JSON (`GET /me/export`, D-55): saved filters, shelf entries and any other per-user catalog rows; it contains all and only the caller's rows, is read-only and audited; the Settings screen bundles it with the identity and reader exports; account deletion removes the same rows.
