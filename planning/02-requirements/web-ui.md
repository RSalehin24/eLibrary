# Requirements - Web UI (WEB)

Status: DRAFT · Service: [web](../05-services/web/README.md)

Scope (D-02, D-16, D-25, D-26, new-architecture section 8): the Angular application on Angular Material (Material Design 3), server-side rendered for public pages with Angular SSR and run as a Node SSR server container (D-39), talking to the services only through the gateway with a client generated from the Rust contracts. The reader renderer is specified in [reader](rdr-reader.md); this file covers the app shell and every screen.

- **REQ-WEB-001** · MUST · inv: INV-WEB-001 · verify: type, review · Every page models its state as an exhaustive type (Loading, Empty, Ready, Error, Forbidden, NotFound, Offline); a missing state is a compile error. (kept from v1)
- **REQ-WEB-002** · MUST · inv: INV-WEB-002 · verify: unit, e2e · The client error model distinguishes 401 (unauthenticated: go to sign-in and keep the target route) from 403 (forbidden: inline "not allowed" and the session stays); the UI never reports a fake "application restarted". (answers X1-090)
- **REQ-WEB-003** · MUST · inv: INV-WEB-003 · verify: unit, e2e · The server-published scope set for the signed-in user drives navigation, route guards (`CanMatch`) and component visibility; the client never re-implements permission rules and the server stays authoritative on every call. (answers X1-008, X1-014)
- **REQ-WEB-004** · MUST · inv: INV-WEB-004 · verify: e2e · One typed route table is the only source of routes and links (including `/books/{slug}/read` and notes deep links); a link checker fails on any dead internal link and unknown paths show a NotFound page. (answers X1-092; kept from v1)
- **REQ-WEB-005** · MUST · inv: INV-WEB-005 · verify: review, e2e · The UI follows Material Design 3 through Angular Material and CDK; components come from the library or documented `shared/` compositions, themes are generated M3 schemes, there is no emoji in labels and no second UI component library without owner approval. (kept from v1)
- **REQ-WEB-006** · MUST · inv: INV-WEB-006 · verify: e2e, review · The look is minimalist: restrained colour, flat tonal surfaces, generous whitespace, elevation only for overlays, error colour only for failure or destruction, no gradients, glass blur or entrance animation. (D-26; answers X1-099)
- **REQ-WEB-007** · MUST · inv: INV-WEB-007 · verify: e2e, review · Light and dark themes are both first-class on every screen, driven by one set of M3 tokens with no per-component override; the default follows `prefers-color-scheme`, a manual choice (System, Light, Dark) persists, the theme is applied before first paint, and "System" always resolves to a concrete value. (answers X1-091)
- **REQ-WEB-008** · MUST · inv: INV-WEB-008 · verify: e2e, review · Text and UI contrast meets WCAG 2.2 AA in both themes (4.5:1 text, 3:1 UI) and every colour comes from a theme token.
- **REQ-WEB-009** · MUST · inv: INV-WEB-009 · verify: e2e · Layouts use four window classes (compact under 600 px, medium 600-839, expanded 840-1199, large from 1200) with adaptive navigation (bottom bar, rail, drawer), no horizontal page scroll from 360 to 1920 px, tables collapsing to lists on compact, and orientation changes keeping position and form state. (D-25; kept from v1 REQ-WEB-005/012)
- **REQ-WEB-010** · MUST · inv: INV-WEB-010 · verify: e2e, review · WCAG 2.2 AA: keyboard operable, visible focus ring, touch targets at least 48 px, screen-reader labels, dialogs with focus trap, live regions for async results, reduced motion and 200% text scaling without clipping. (answers X1-103, X1-104; kept from v1)
- **REQ-WEB-011** · MUST · inv: INV-WEB-011 · verify: unit, review · UI strings come from `bn` and `en` catalogs with identical key sets (a missing key fails the build); the default language comes from `Accept-Language` falling back to Bengali (D-08); date and time zone come from user or server configuration, not hard-coded. (answers X1-101; kept from v1)
- **REQ-WEB-012** · MUST · inv: INV-WEB-012 · verify: review · Bengali typography uses self-hosted Noto Sans Bengali (UI) and Noto Serif Bengali (reading) with line height 1.6-1.75, no uppercase transforms and no positive letter-spacing, so conjuncts render correctly.
- **REQ-WEB-013** · MUST · inv: INV-WEB-013 · verify: type, static · The app is strict TypeScript; wire types and the API client are generated from the Rust contract schema (regeneration yields no diff); `any`, non-null assertions and unchecked casts do not appear outside the generated boundary. (kept from v1)
- **REQ-WEB-014** · MUST · inv: INV-WEB-014 · verify: review · The screens are: Sign-in and auth card shell (sign-in, reset request and confirm, invite acceptance, TOTP step, one card with different steps), Library, Book detail, Reader, Import workspace (operator), Catalog management (`manage_catalog`: edit, unpublish, delete, export, contributors; no approval queue, D-49), Users and access (admin), Settings. Navigation items show only the screens the user's scopes allow. (new-architecture section 8)
- **REQ-WEB-015** · MUST · inv: INV-WEB-015 · verify: e2e · Library is one screen for browse, search, filters, My Books and Kindle: scope chips (All, My Books, Sent to Kindle), a facet tab bar (category, series, contributors, publisher), a card/list toggle, one filter sheet, filters and sort in the URL, skeletons sized to final content, and Bengali-aware sorting. Anonymous visitors see browse, search and preview only.
- **REQ-WEB-016** · MUST · inv: INV-WEB-016 · verify: e2e · Book detail has tabs (overview, metadata, files); Files shows download and Kindle actions with delivery status only when the scopes allow; the page shows the honest read-limit notice and a Read action that opens the reader through a ticket.
- **REQ-WEB-017** · MUST · inv: INV-WEB-017 · verify: e2e · Import workspace shows catalog sync, requests, duplicate review, jobs and the source credential status in one bucket-rail screen over one table component and one live stream; destructive actions use one Material confirm dialog and every command reports a per-item result in a snackbar. (answers X1-096, X1-100)
- **REQ-WEB-018** · MUST · inv: INV-WEB-018 · verify: e2e · Users and access (admin) manages invites, accounts and grants per user through batched, atomic requests (identity's batch grants route, D-54), with grants visible in the user's detail drawer. (answers X1-061)
- **REQ-WEB-019** · MUST · inv: INV-WEB-019 · verify: e2e · Settings holds theme (System/Light/Dark), language, profile and TOTP setup as a stepper dialog that requires re-authentication to change; reader preferences are stored per user; Settings also offers one JSON download that bundles the identity, reader and catalog per-user exports (D-55).
- **REQ-WEB-020** · MUST · inv: INV-WEB-020 · verify: unit, e2e · Mutations use the session cookie with a CSRF header checked by the gateway without an extra GET per mutation; there is no browser health poll and no forced page reload; a lost connection retries with backoff and keeps form state. (answers X1-078)
- **REQ-WEB-021** · MUST · inv: INV-WEB-021 · verify: type, e2e · The reading ticket lives only in memory (never in a URL, storage or log), is refreshed once on expiry, and unsaved progress is flushed on page hide. (answers X1-003)
- **REQ-WEB-022** · MUST · inv: INV-WEB-022 · verify: review, e2e · Public pages (browse, detail) are server-side rendered with Angular SSR (D-39) so the first HTML response carries title, canonical URL, meta tags and structured metadata with metadata only; preview text is not public, needs sign-in and is marked `noindex` (D-34, D-09).
- **REQ-WEB-023** · MUST · inv: INV-WEB-023 · verify: unit, e2e · Tests import the real units (no source-grep tests, no inlined copies); API mocks come from the generated schema; end-to-end tests are hermetic with no fixed sleeps; every acceptance criterion maps to an automated test. (answers X1-110, X1-111, X1-112)
- **REQ-WEB-024** · MUST · inv: INV-WEB-024 · verify: review, e2e · The `web` container is a Node SSR server, not a set of static files; it keeps the TypeScript client generated from the Rust contracts as the only API client and reaches services only through the gateway (D-39, REQ-WEB-013).
