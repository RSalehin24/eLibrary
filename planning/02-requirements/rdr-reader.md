# Requirements - Reader (RDR)

Status: DRAFT · Service: [reader](../05-services/reader/README.md)

Scope (D-28, D-31, new-architecture section 5): the reader service builds a sanitized reading copy of each published EPUB, issues short reading tickets after an entitlement check, serves the whole rendered book against a ticket, and stores per-user progress, bookmarks, highlights and notes. It absorbs the reading-copy part of CON and the personal-data part of LIB. The browser renderer lives in [web](web-ui.md). Open detail of D-28 (server HTML vs whole-book package) is resolved here as a single whole-book package rendered by a purpose-built browser renderer, per the architecture brief.

- **REQ-RDR-001** · MUST · inv: INV-RDR-001 · verify: model, prop · On `book.published` the reader fetches the EPUB from catalog, parses it once (OPF, spine, TOC, XHTML, images, fonts) and stores a reading copy keyed by `(book_id, version)`; the step is idempotent per key. (kept from v1 REQ-CON-011, changed)
- **REQ-RDR-002** · MUST · inv: INV-RDR-002 · verify: prop · The reading copy is a deterministic function of the EPUB and the parser version: the same input gives byte-identical output.
- **REQ-RDR-003** · MUST · inv: INV-RDR-003 · verify: type, fuzz · Every XHTML document is sanitized through an allow-list into a `SafeHtml` type; scripts, inline handlers, external loads and unknown URL schemes cannot appear in stored output; resource links are rewritten to reading-copy resources; the sanitizer is idempotent. (answers X1-004)
- **REQ-RDR-004** · MUST · inv: INV-RDR-004 · verify: db, drill · A reading copy has states Building, Ready, Failed, Withdrawn; only Ready is served; a copy is replaced only atomically by a newer Ready copy; a copy of an unpublished or tombstoned book stops being served; annotations are never deleted by a copy change. (answers X1-032)
- **REQ-RDR-005** · MUST · inv: INV-RDR-005 · verify: model, e2e · `POST /api/reader/books/{slug}/open` checks the `read` scope (separate from `preview`, D-41) with identity and that the version is published and not deleted, applies the `read_once` rule, and only then returns a reading ticket. Having the book on a shelf grants nothing. (answers X1-001, X1-009, X1-058)
- **REQ-RDR-006** · MUST · inv: INV-RDR-006 · verify: type, e2e · A reading ticket is bound to user, book and version, valid for 15 minutes, carried in a header or the body and never in a URL; the reader verifies it only by asking identity (internal `verify` call, D-37) and never by checking a signature locally; the book handler accepts only a `Verified<ReadingTicket>`. (answers X1-003)
- **REQ-RDR-007** · MUST · inv: INV-RDR-007 · verify: model, e2e · A ticket is revocable immediately: every redemption goes through identity's `verify`, which re-checks the user's grants and active state and the book's published state (D-37), and the events `user.disabled`, `grant.changed` and `book.unpublished` invalidate outstanding tickets. (answers X1-003)
- **REQ-RDR-008** · MUST · inv: INV-RDR-008 · verify: type, e2e · `GET /api/reader/tickets/{ticket}/book` returns the whole rendered book as one package (manifest, TOC, chapters, resources); the EPUB file is never served by the reader and there is no per-chapter content route. (D-28)
- **REQ-RDR-009** · MUST · inv: INV-RDR-009 · verify: model, db, e2e · Read-once is consumed atomically when a ticket is successfully redeemed for the book, not at open and not when the file or copy is missing; two simultaneous redemptions consume it once; the rule applies equally to every role. (answers X1-020)
- **REQ-RDR-010** · MUST · inv: INV-RDR-010 · verify: review · The records and the UI state the honest limit: serving the whole book means a reader can copy it. Controls are entitlements, short tickets, rate limits and an audit log of opens; this is not DRM. (answers X1-020)
- **REQ-RDR-011** · MUST · inv: INV-RDR-011 · verify: db, e2e · Every ticket issue and redemption is rate limited per user and written to an append-only audit log with user, book, version and outcome, retained 1 year (D-40). (answers X1-084)
- **REQ-RDR-012** · MUST · inv: INV-RDR-012 · verify: model, db · Progress is one record per (user, book) with a strictly increasing revision (a stale write is a no-op), a bounded locator long enough for any anchor, a 0-100 percent validated at the boundary, and an idempotent PUT; position is a section plus offset, not only a chapter. (answers X1-056, X1-057)
- **REQ-RDR-013** · MUST · inv: INV-RDR-013 · verify: db, e2e · Bookmarks can be created, listed, jumped to and deleted; creating the same bookmark twice returns the existing one with a typed result, never a 500. (answers X1-038)
- **REQ-RDR-014** · MUST · inv: INV-RDR-014 · verify: unit, e2e · Highlights (five colours defined once, kind highlight or quote) and notes can be created, edited, recoloured and deleted, through the keyboard as well as pointer and touch, with a labelled dialog for note text and visible, retryable errors. (answers X1-094, X1-103)
- **REQ-RDR-015** · MUST · inv: INV-RDR-015 · verify: prop · Annotations and bookmarks carry an anchor (section id, text quote with prefix and suffix, offset); when a book version changes the server re-anchors them against the new reading copy (D-46), and those that cannot be placed become Orphaned (outcome `orphaned`, kept and flagged) and stay visible, never deleted; resolving an anchor returns a location or Orphaned, never an error. (answers X1-094)
- **REQ-RDR-016** · MUST · inv: INV-RDR-016 · verify: type, db, e2e · Progress, bookmarks, highlights and notes require the signed-in session in addition to the ticket and are readable and writable only by their owner, enforced by the user id from the verified identity header and by row-level policy. (answers X1-058)
- **REQ-RDR-017** · MUST · inv: INV-RDR-017 · verify: unit, e2e · A user can export all of their own reading data as JSON (`GET /me/export`, bundled by Settings with the identity and catalog exports, D-55); an admin account deletion removes it. (answers X1-041)
- **REQ-RDR-018** · MUST · inv: INV-RDR-018 · verify: e2e · The notes page lists a user's annotations across books with deep links that open the exact location, or show the orphan state; the links use the one typed route table. (answers X1-092)
- **REQ-RDR-019** · SHOULD · inv: INV-RDR-019 · verify: unit · A user can export their notes and highlights as Markdown and JSON.
- **REQ-RDR-020** · MUST · inv: INV-RDR-020 · verify: e2e, review · The reader offers light, dark and sepia themes (matching the app by default, then the user's own choice, owned by one state) and typography controls for size, family, line height and margins with Bengali-tuned defaults; theming uses CSS variables on the sanitized container with no forced overrides of publisher markup. (answers X1-062, X1-095)
- **REQ-RDR-021** · MUST · inv: INV-RDR-021 · verify: e2e, review · The reader meets WCAG AA: every action works by keyboard (page and section stepping, TOC, annotate), browser zoom is not hijacked, Esc leaves immersive mode, targets are at least 48 px, motion respects reduced-motion, and location changes are announced. (answers X1-103)
- **REQ-RDR-022** · MUST · inv: INV-RDR-022 · verify: type, e2e · Every async path of the reader has loading, error and retry states: copy still building, forbidden, not found, ticket expired (one silent re-open, then a message), network offline; none ends in a blank page or a browser alert. (answers X1-093)
- **REQ-RDR-023** · SHOULD · inv: INV-RDR-023 · verify: unit, e2e · In-book search finds text within the reading copy and jumps to the result. (new; cheap only)
- **REQ-RDR-024** · MUST · inv: INV-RDR-024 · verify: model, prop · The reader consumes catalog and identity events from a stored cursor, tolerates duplicates and restarts, and rebuilds missing copies on startup.
- **REQ-RDR-025** · MUST · inv: INV-RDR-025 · verify: prop, e2e · Reader GET handlers are side-effect free (a missing resource never changes state); the book package and its resources are served with a restrictive content-security policy and nosniff. (answers X1-004, X1-032)
- **REQ-RDR-026** · MUST · inv: INV-RDR-026 · verify: db, e2e · Reader preferences (theme, font family, size, line height, margins) are stored per user in the reader service (table `preferences`, routes `GET` and `PUT /me/preferences`, D-48), readable and writable only by their owner, and applied on every device after sign-in. (D-48)
