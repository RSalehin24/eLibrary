# Requirements — Access (ACC)

Status: DRAFT · Service: [identity](../05-services/identity/README.md) (D-27: the former access service is merged into identity; ids keep the ACC prefix)

- **REQ-ACC-001** · MUST · inv: INV-ACC-001 · verify: model, prop · Anonymous subjects may only use the public routes (browse/search metadata, published preview text, sign-in, invite acceptance, password reset, demo sign-in). They can never Read full text, Download, SendToKindle, or perform any management action.
- **REQ-ACC-002** · MUST · inv: INV-ACC-002 · verify: model, prop · Reading full text requires an authenticated, Active account and an explicit grant row (user, scope, optional book, optional expiry, granted_by) for the `read` scope. Ownership, "My Books" and shelves never grant access; there are no wildcard roles. Decided (D-04, new-architecture section 10): a new reader holds `browse`, `preview`, `read` on published books and `kindle` by default; `download` and `read_once` only by explicit grant; the default policy is configuration, not code.
- **REQ-ACC-003** · MUST · inv: INV-ACC-003 · verify: model, type · Authorization is deny-by-default. `decide` is total and returns `Allow` or `Deny(reason)`; there is no code path that authorizes without calling it.
- **REQ-ACC-004** · MUST · inv: INV-ACC-004 · verify: model, prop · Expired or revoked grants have no effect, evaluated against an injected clock.
- **REQ-ACC-005** · MUST · inv: INV-ACC-005 · verify: model, prop · Adding a grant never removes an existing permission (monotonicity). The only non-monotonic rule is read-once consumption.
- **REQ-ACC-006** · MUST · inv: INV-ACC-006 · verify: model, prop, e2e · Read-once allows exactly one redeemed reading ticket per account and book. The opening is consumed when the ticket is successfully redeemed for the book (see REQ-ACC-013), not at open time and not when a file is missing. A reconnect or retry with the same ticket is not a new opening.
- **REQ-ACC-007** · MUST · inv: INV-ACC-007 · verify: model, e2e · Demo accounts and accounts without management grants cannot invoke mutating administrative actions.
- **REQ-ACC-008** · MUST · inv: INV-ACC-008 · verify: type, prop, fuzz · Reading tickets are signed, valid at most 15 minutes, bound to user, book and version, carried in a header or body (never a URL), and revocable through the grant version. The reader verifies them; internal calls between services additionally carry an internal service token.
- **REQ-ACC-009** · MUST · inv: INV-ACC-009 · verify: model, e2e · Management actions require a session that completed TOTP whenever the account requires TOTP.
- **REQ-ACC-010** · MUST · inv: INV-ACC-010 · verify: prop · Decisions do not depend on grant order and are deterministic for identical inputs.
- **REQ-ACC-011** · MUST · inv: INV-ACC-011 · verify: db, e2e · Every grant creation, change and revocation is recorded in the append-only audit log in the same transaction.
- **REQ-ACC-012** · SHOULD · inv: INV-ACC-012 · verify: model, prop · Unpublished (Draft/Archived) books are visible only to subjects with metadata or management grants; to others they behave as nonexistent.
- **REQ-ACC-013** · MUST · inv: INV-ACC-006, INV-ACC-008 · verify: model, prop, e2e · Ticket redemption is idempotent for the same ticket; a ticket for another user, book or version, an expired ticket, or one issued before a `grant.changed`/`user.disabled` revocation is rejected. Honest limit: serving the whole book lets a reader copy it; controls are entitlements, short tickets, rate limits and an audit log of opens, not DRM.
- **REQ-ACC-014** · MUST · inv: INV-PLT-009 · verify: model, prop · Identity publishes `user.disabled` and `grant.changed` through its events outbox (`GET /internal/events?after=<cursor>`), written in the same transaction as the change; consumers (reader, catalog caches) apply each event idempotently from a stored cursor and tolerate duplicates and restarts.
- **REQ-ACC-015** · MUST · inv: INV-ACC-003 · verify: type, e2e · Every `/api/*` route declares its required scope in code; a route without a declaration is rejected at startup (fail closed). Caddy calls identity `/internal/authorize` for every `/api/*` request except the public routes; services trust only the identity headers from Caddy.
