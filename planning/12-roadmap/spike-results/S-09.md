# S-09 result: does the monthly backup work and how long does it take?

Status: DONE for the sample stage (2026-11-20). Re-run when real data and the file volumes exist.

Method: `deploy/scripts/backup-dry-run.sh` seeds a sentinel row in two databases, runs `backup.sh`, stops the stack, runs `restore-drill.sh` into a separate Compose project (`elibrary-drill`, empty volume), then reads the sentinels back as the service roles.

| Measure | Result |
|---|---|
| Backup of five databases | 2 s, 52 KB (sample data only, so not representative) |
| Restore drill, empty project to healthy stack | 38 s with the six sample services; 73 s with the ten-container stack (2026-11-20) |
| Manifest checksums | verified before any restore; a tampered dump is refused (exit 1, nothing started) |
| Row counts per table | identical after restore (script fails otherwise) |
| Sentinel rows | present, readable by the owning service role |
| Existing backup directory | never overwritten (exit 1) |
| Migrate one-shots after restore | found the schema current; all services healthy |

The dump runs in the `backup` one-shot container (profile `backup`, postgres:16 image, read-only, secret file, `deploy/scripts/backup-job.sh`); `backup.sh` is a thin wrapper that runs it as the invoking user into a new host directory. Scripts: `deploy/scripts/backup.sh`, `deploy/scripts/restore-drill.sh` (the INV-PLT-015 check script), `deploy/scripts/backup-dry-run.sh`.

## Not covered yet

- **Encryption and offsite copy**: the tool (`age` or `restic`) is an open owner decision; backups are written unencrypted into a `0700` directory with `0600` files.
- **File volumes** (`identity_files`, `catalog_files`, `ingestion_files`) do not exist yet.
- **Outbox cursor reconciliation** and **search index rebuild**: no outbox or index exists yet.
- **Secrets bundle** restore: the drill reuses the host's secret files.
- **Scale**: real size and duration need the 5,000-book seed (P4); RTO 4 h is untested at scale.
