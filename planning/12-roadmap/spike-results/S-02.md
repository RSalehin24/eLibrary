## Findings

1. **Allowed hosts (SSRF protection).** The server refuses any Host header not allow-listed (`NG_ALLOWED_HOSTS`, or `security.allowedHosts` in `angular.json`): a per-environment deployment setting.
2. **Proxy headers.** `X-Forwarded-*` is ignored unless trusted: `trustProxyHeaders` is set to `x-forwarded-host` and `x-forwarded-proto` only, because the sole caller is Caddy.
3. **SSR data calls.** A relative `/api/...` URL resolves to the public host, which the container cannot reach. An interceptor prefixes `/api/` with `ELIBRARY_API_ORIGIN` on the server only (INV-WEB-024: browser and server share one client).
4. **Material 22 has no navigation rail, bottom navigation bar, side sheet or search component** (its component folders are `sidenav`, `bottom-sheet`, `toolbar`, `tabs`, `menu` and others). These must be built from CDK and tokens: the gap is composable but not yet proven.
5. `ulimit -v` cannot cap Node or esbuild (V8 and Go reserve large virtual ranges); heavy web jobs use `systemd-run --user --scope -p MemoryMax=20G` instead (a deviation from the CLAUDE.md wording, same intent).

## Lint and accessibility (D-71, D-72)

- **ESLint** (`eslint` 10.14, `typescript-eslint` 8.72.2 strict type-checked, `angular-eslint` 22.8.0) enforces section 16: `max-params` 3, `max-lines-per-function` 30, `max-depth` 2, `complexity` 10, no magic numbers, no `any`, no `!`, no `as` assertions, switch exhaustiveness, no browser globals (SSR). Turning the strict rules on found real defects in the first code: a deprecated `withFetch`, untyped route data (now parsed at the edge by `parseBook`), void-returning expressions and a magic port number. One rule is tuned: `no-extraneous-class` allows decorated classes (Angular components).
- **Playwright 1.65.1 and axe-core 4.14.1** (Chromium headless shell, 126 MB, in `~/.cache/ms-playwright`): the book page has **0 serious or critical axe violations** in light desktop, dark desktop and a 375 px mobile viewport; a fresh load logs no console errors or warnings (no hydration errors). A sanity run on a deliberately broken page reports `button-name`, `image-alt` and `document-title`, so the check is not vacuous.
- `cargo xtask check` now runs web lint, build, unit tests and e2e.
