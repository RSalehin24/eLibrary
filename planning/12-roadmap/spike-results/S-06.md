# S-06 result: does the stack fit the host and start in time?

Status: DONE for the sample stage (2026-11-20). Re-run when real services, `web`, `ingestion-worker` and `backup` exist.

Method: `deploy/scripts/stack-budget.sh` on the dev machine (30 GB RAM), images prebuilt, six sample services plus `postgres` and `caddy` (nine long-running containers, five migrate one-shots).

| Measure | Target | Result |
|---|---|---|
| Cold start to all healthy (`up -d --wait`) | ≤ 90 s (REQ-NFR-014) | 13.5 s |
| Idle memory, all containers | ≤ 4 GB (REQ-NFR-005, provisional) | 65 MiB |
| Memory after 400 requests (20 in parallel, through Caddy) | ≤ 8 GB | 69 MiB |
| Restart of one service to healthy | ≤ 15 s | 1.4 s |

Meaningful only as a floor: the services have no domain logic, no data and no `web`, so the real figures will be much higher. The targets were met with a very large margin; the open question stays whether real services fit.

## Findings

1. **SIGTERM was ignored.** As PID 1 the service did not handle SIGTERM, so a restart waited Docker's 10 s grace period (restart 11.4 s). Fixed in `platform-startup` (graceful shutdown of both listeners; test `svc-gateway/tests/shutdown.rs`); restart is now 1.4 s.
2. **First health probe waited one interval** (restart 15.2 s before the fix). `HEALTHCHECK --start-interval=1s` with a 10 s start period probes quickly while starting.
