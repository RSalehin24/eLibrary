## A. Host-to-host migration toolkit (`migration/`)

**T1 Purpose.** Move the live production stack from the old server (AWS Ubuntu, "source") to a new one (DigitalOcean, "target") by one command, `migration/migrate.sh` (usage text, `migrate_steps/configuration_and_arguments.sh:35-37`). Phases: preflight (read-only checks), snapshot (freeze source, dump), restore (upload, rebuild target), verify (health, optional nginx/certbot edge). Flags: `--phase`, `--dry-run`, `--resume`, `--keep-staging`, `--allow-target-reset`, `--skip-edge`, `--config` (configuration_and_arguments.sh:16-44,128-177). `migrate.sh` (18 lines) merely sources the six step files in order (migrate.sh:6-18); `main()` at edge_verify_and_entrypoint.sh:90-117 orchestrates. README points to `docs/operations/migration.md` (not read, outside slice; README.md:5).

**T2 Operating model it reveals.** Production = one VM running Docker Compose (`deploy/compose/docker-compose.yml`) with services postgres, redis, backend, backend-init (one-shot migrate/init), frontend, worker (Celery default queue `celery`), processing-worker (queue `processing`), beat (preflight_remote_checks.sh:166-176; source_freeze_checks.sh:106,142; target_restore_checks.sh:126,157). Host nginx + certbot as edge (`deploy/scripts/setup-host-nginx.sh`, edge_verify_and_entrypoint.sh:14), Cloudflare in front for DNS (maybe_prompt_for_cloudflare_change, preflight_remote_checks.sh:79-87). App state = Postgres cluster + Redis RDB + `app/backend/storage` file tree + `deploy/env/.app.env`; the same repo path is recreated on the target (configuration_and_arguments.sh:121-125; migrate.env.example:1-3). Backend health endpoint `/api/csrf/`, frontend on a separate port (4173 default), backend 8000 (config:190-191; preflight:183-184). Database name default `bangla_library`, user `postgres` (snapshot_capture.sh:13; source_freeze_checks.sh:231). Two Celery queues and Redis as broker are operational state that must be drained before cut-over.

**T3 Config handling.** `migrate.env.example` (16 lines): TARGET_USER, TARGET_IP and optional overrides TARGET_PUBLIC_BASE_URL, TARGET_PUBLIC_API_ORIGIN, TARGET_FRONTEND_BASE_URL; everything else is inherited from `deploy/env/.host.env` (DEPLOY_USER_NAME, DEPLOY_IP, DEPLOY_REMOTE_APP_DIR, DEPLOY_DOMAIN, DEPLOY_CERTBOT_EMAIL, BACKEND_PORT, FRONTEND_PORT, DEPLOY_DOCKER_VERSION, DEPLOY_NGINX_VERSION/CONF_DIR/CONFIG_NAME; configuration_and_arguments.sh:74-118). Optional vars not in the example but supported: SOURCE_/TARGET_ SSH_KEY_PATH, SSH_PASSWORD, SUDO_PASSWORD (ssh.sh:21-32), STRICT_HOST_KEY_MODE (default accept-new), DRAIN_TIMEOUT_SECONDS 900, HEALTHCHECK_TIMEOUT_SECONDS 240, KEEP_SOURCE_DOWN_ON_SUCCESS, KEEP_STAGING default 1 (config:183-201). `ensure_config_file` copies the example and aborts so the operator fills it (lib/config.sh:1-12). Config is loaded by `eval` of shell-quoted exports produced by `automation/lib/env_tools.py shell-export` (config.sh:14-19).

**T4 Preflight (read-only)** (source_freeze_checks.sh:72-94, preflight_remote_checks.sh): validate required keys (note TARGET_IP listed twice, configuration_and_arguments.sh:263,266); local tools bash/ssh/scp/tar/gzip/python3 + sha256sum|shasum (+sshpass if passwords); SSH connectivity for both ends (BatchMode when no password; failure message tells operator to run ssh-copy-id, preflight:96); 10-second timed Cloudflare/DNS confirmation prompt (default "n", continues anyway); OS must be Ubuntu/Debian (preflight:111); passwordless sudo or password; source layout files exist (docker-compose.yml, install-docker.sh, setup-host-nginx.sh, common.sh, storage dir, .app.env; preflight:128-138); source stack healthy (postgres/redis/backend must be healthy, others running; HTTP probe of backend and frontend; preflight:166-190); target ports 80/443/backend/frontend free (preflight:192-222); target app dir state missing/empty/resumable(bundle-id marker)/resettable/occupied (preflight:224-265); disk space local (raw size x1.25 + 100 MB) and target (raw x2 + 100 MB) (source_freeze_checks.sh:53-55); edge readiness = domain DNS must resolve to TARGET_IP, else edge setup skipped with reason (preflight:49-77); writes `target-env-overrides.env`.

**T5 Snapshot (downtime)** (source_snapshot_capture.sh:143-167; source_freeze_checks.sh:96-249): stop beat, frontend, backend (freeze writes) -> poll Celery `inspect` active/reserved/scheduled and Redis `LLEN celery`/`LLEN processing` every 5 s until all zero or 900 s timeout, then restart source and abort (freeze:147-179) -> stop workers -> copy `.app.env` (contains secrets) -> stream tar.gz of repo excluding .git, storage, env files, node_modules, dist, logs, test artefacts -> tar.gz of `storage` -> `pg_dumpall --globals-only` plus `pg_dump --clean --if-exists --create` of the app DB piped through awk that strips the bootstrap role's CREATE/ALTER ROLE lines and `gzip -1` (freeze:223-240) -> Redis `SAVE` + copy `/data/dump.rdb` -> metadata manifest (git commit, SHA-256 of every artefact, per-table row counts via a `pg_temp` PL/pgSQL function, total rows, a SHA-256 over the table=count list, role count, Redis DBSIZE/queue lengths/used memory, storage file count and bytes; snapshot_capture.sh:8-129) -> `checksums.sha256` and local verify. Source restarted at the end for `--phase snapshot`, or in `finalize_success` (edge:67-71), and also on any failure via `trap on_exit` (edge:81-88).

**T6 Restore** (target_restore_checks.sh:162-185): scp 8 artefacts to `/tmp/<bundle>` on target; verify checksums remotely; wipe/prepare app dir (only if reset allowed or resumable); untar app, write `.migration-state/bundle-id` marker, install `.app.env`, merge overrides with `env_tools.py merge --non-empty-only`; install Docker if missing or version differs (via repo script); `compose down --volumes` then `up postgres redis`; wait pg_isready/redis PONG; restore SQL through psql `ON_ERROR_STOP=1`; replace Redis dump by stop / `docker cp` / start; untar storage and chown/chmod; **compare** source vs target pre-start: table count, total rows, role count, row-count hash, Redis dbsize/queue lengths, storage file count/bytes (target_restore_checks.sh:101-109), abort on any mismatch; run `backend-init` one-shot, wait for exit code 0; start app services. **Verify**: container status + HTTP probe (:187-211), re-compare live DB/storage summaries (:213-233), optional nginx/certbot edge via repo script and HTTPS probe of `/` and `/api/csrf/` (edge:1-28). Phase markers `.phase-<name>.done` in the bundle dir give resume (config.sh:67-80; edge:51-58).

**T7 Library helpers.** `bundle.sh` (55): hash, checksum manifest, local verify, metadata append, free-space via df. `compose.sh` (23): builds remote script text that cds, sources `automation/lib/common.sh`, loads `.app.env` and sets `COMPOSE_ARGS`. `config.sh` (111), `logging.sh` (44: timestamped log to stdout and `LOG_FILE`, `die`, DRY RUN wrapper), `ssh.sh` (177: role-based ssh/scp wrappers; optional `sshpass`; `remote_sudo` can pipe a sudo password into `sudo -S`).

**T8 Issues / pain revealed by the toolkit.**
- **T8.1** Cut-over requires full downtime (writes frozen, workers drained up to 15 minutes) and a whole-cluster dump; no incremental/replica path. Dump/restore of book HTML in DB and `storage` tree scales with library size.
- **T8.2** Secrets travel: `.app.env` (all production secrets) and `pg_dumpall --globals-only` (role password hashes) are copied to the operator's laptop staging dir and /tmp on the target; `KEEP_STAGING` defaults to 1, so they remain on disk after success (config:201). `SSHPASS`/sudo password are accepted in config and, for sudo, piped into a remote command line (ssh.sh:173), exposing them in remote process args/history. `StrictHostKeyChecking=no` mode available (ssh.sh:7-8).
- **T8.3** `finalize_success` restarts the source stack by default after a successful migration (KEEP_SOURCE_DOWN_ON_SUCCESS=0; edge:67-71): two live copies of the system (workers, beat, scrapers) unless the operator intervenes; split-brain risk (duplicate scheduled automation, double e-mail).
- **T8.4** Dry run still touches nothing but only logs; `--dry-run` for phases other than preflight just marks phases done (snapshot:144-147, restore:164-167, verify:37-40) so a later `--resume` would skip real work (marker semantics bug).
- **T8.5** Redis state (broker queues, possibly sessions/cache) is copied as an RDB; the design depends on Redis persistence for correctness; the Celery queues are asserted empty, so the copy only matters for non-queue keys.
- **T8.6** Pre-start comparison relies on `pg_stat_user_tables` and exact `count(*)` per table (slow on large tables) and on row counts, not content; the hash covers counts only.
- **T8.7** Hard-coded cloud names (AWS/DigitalOcean/Cloudflare) in usage text; Docker version pin; `bash -lc` string-interpolated remote scripts with `eval` of config (injection-sensitive if a config value contains shell metacharacters; mitigated by `shlex.quote`).
- **T8.8** Branded default DB name `bangla_library` and dir `library_app` (config:187) tie ops to the old naming.
- **T8.9** Requirement for rebuild: the operator needs a documented, tested backup/restore and host-move procedure with verification counts, drain-before-freeze, resumable phases and no secrets at rest; prefer object storage + managed/continuous PG backups, which removes freeze and storage tarball.
