## 3. Authentication flows (step by step)

Common setup: Django session cookie auth; DRF SessionAuthentication enforces CSRF on authenticated unsafe requests (settings not read here; csrf cookie issued by GET `/api/csrf/`). No TOKEN auth.

3.1 Login (`POST login/`): throttle check (anon IP, 10/hour). `authenticate(request, email, password)` (USERNAME_FIELD email; ModelBackend rejects inactive users: results in invalid_credentials). If `user.has_totp_enabled` (confirmed TOTPDevice exists): empty `otp_token` -> 400 code `otp_required`; else take FIRST confirmed device (no ordering) and `verify_token`; failure -> `otp_invalid`. Success: `login()` and return UserSerializer. Users with `totp_required` but no confirmed device log in without OTP and are then fenced by middleware (3.8). Passwords: no lockout beyond the throttle; throttle counts all attempts, success included (DRF throttles count every request).
3.2 Demo login: `GET demo-login/` as above. Hard-coded default email and password in settings defaults (`demo_user.library@...`, password literal in config/settings.py:108, a committed secret in the legacy repo).
3.3 Invite: super admin POST `users/` with send_invite_email true -> user created with unusable password, `email_setup_pending=True`; nonce incremented 0->1 inside `send_account_setup_email`; email built with `PasswordLinkTokenGenerator` token and link `{FRONTEND_BASE_URL}{PASSWORD_CREATE_FRONTEND_PATH}?uid=<b64 pk>&token=<token>` (path `/create-password` per doc). Subject/templates `registration/account_invite_subject.txt`, `account_invite_email.html` (+ optional `.txt` sibling, fallback strip_tags). Sender: `ACCOUNT_INVITE_FROM_EMAIL` or `DEFAULT_FROM_EMAIL`, quotes stripped, display name default "RSalehin24 Library". `message.send(fail_silently=False)`; delivered<1 raises RuntimeError.
3.4 Setup email / create password: frontend calls `password-reset/validate/` then `password-reset/confirm/`. Token check uses `password_link_token_generator` (hash of pk, password, last_login (second precision), timestamp, email, `password_setup_nonce`, `email_setup_pending`). Fallback (legacy): if `email_setup_pending` false and nonce==0, also accepts Django's stock PasswordResetTokenGenerator. On confirm with `email_setup_pending`: set password, nonce +1 (invalidates the link), `email_setup_pending = totp_required and not has_totp_enabled` (stays pending until TOTP is confirmed). If still requiring TOTP setup -> session login and next_step totp_setup; else next_step login.
3.5 Resend: `POST users/<id>/resend-setup-email/` (section 2 #18). Under `select_for_update`, nonce +1, send again. Old links die because nonce is part of the hash. Button disappears when `email_setup_pending` false.
3.6 Password reset (self-service): `POST password-reset/`: look up active user by `email__iexact` (first by pk). Not eligible when None, `email_setup_pending`, or unusable password (False -> 404 message). Locks user row, nonce +1 (kills all earlier links), renders email using `registration/password_reset_subject.txt` and `password_reset_email.html` with `reset_link_timeout_label` computed from PASSWORD_RESET_TIMEOUT (default 6*60*60 = "6 hours"), link `{frontend}/reset-password/confirm?uid&token` (frontend path from `PASSWORD_RESET_FRONTEND_PATH`). `format_duration_label`: whole hours -> "N hour(s)", else minutes (ceil), min 1. Token expiry enforced by Django's `check_token` using PASSWORD_RESET_TIMEOUT. Confirm: sets password only (nonce unchanged if not pending, but password change itself invalidates since password is in hash). Does not revoke other sessions of the user (Django sessions remain valid unless SessionAuth hash changes; session auth hash is derived from the password, so existing sessions are invalidated by the password change; but `login()` here re-sessions only the TOTP-required case).
3.7 TOTP setup/confirm/cancel/disable: flows in endpoints 22-25. QR: `qrcode` library optional (empty string if ImportError); SVG path image. Secret presented in base32 without padding. Confirm token verify is django-otp default (drift tolerance per library defaults, not set). After confirm of an invited user, `email_setup_pending` cleared (only if usable password).
3.8 Forced TOTP middleware (`common/middleware.py`): for any path starting `/api/` not in the allowed set {session, demo-login, logout, profile, 2fa/status, 2fa/setup, 2fa/confirm, 2fa/cancel, 2fa/disable, `/api/csrf/`} and authenticated user with `requires_totp_setup` (totp_required and no confirmed device), return 403 `{detail:"TOTP setup is required for this account before continuing.", code:"otp_setup_required"}`. Not allowed-listed: `/api/health/` (health is also blocked for such users, harmless), login/password-reset paths (these are not blocked when unauthenticated; but an authenticated TOTP-pending user cannot call `password-reset/confirm`, though that view rejects authenticated anyway). Non-API paths (e.g. `/media/`, django admin) are not fenced. The profile endpoint IS allowed, so the user can change password etc. while pending.
3.9 Sessions: Django sessions via `login`/`logout`; `update_session_auth_hash` after profile password change; no explicit session cookie age found in the files I read; no "log out everywhere" and no listing of active sessions. No session invalidation on admin deactivate besides ModelBackend `is_active` check at each request (SessionAuthentication loads user through `get_user`, which rejects inactive via `user_can_authenticate`, so disabled users are logged out).
3.10 CSRF: GET `/api/csrf/` returns token and cookie; DRF SessionAuthentication enforces for authenticated requests only; login endpoint (AllowAny, unauthenticated) is csrf-exempt in DRF (authentication returns None), so login CSRF is not enforced.
3.11 Throttles (`common/throttles.py`): LoginRateThrottle scope login 10/hour (env THROTTLE_LOGIN), RegisterRateThrottle register 5/hour (unused route), PasswordResetRateThrottle password_reset 5/hour, SubmissionRateThrottle (UserRateThrottle) submission 40/hour (used by ingestion, not here). All anon throttles key by client IP (REMOTE_ADDR/X-Forwarded-For per DRF NUM_PROXIES). No throttle on: demo-login, password-reset/validate, password-reset/confirm, 2fa/confirm, resend email, kindle send, and reader tokens.

## 4. Authorization (permission functions and where used)

`common/permissions.py`:
- `granted_scope_queryset(user, book=None)`: active grants (is_active and not expired) for user; with `book=None` only global (book, category, contributor all null); with a book: global OR book grant OR category grant where `category__books=book` OR contributor grant where contributor has an AUTHOR contribution to the book.
- `user_has_scope(user, scopes, book=None)`: False if anonymous; True if `is_superuser or is_staff`; else exists grant with scope == `admin:full_control` OR in `scopes`. (Hence `is_staff` is a full bypass and `admin:full_control` anywhere in scope is a wildcard.)
- `user_owns_book(user, book)`: `book.user_owns_book` annotation if present else `book.user_books.filter(user=user).exists()`.
- `user_has_read_once_limit(user, book)`: False for anonymous, superuser or owner; requires user_has_scope read:once; False if user_has_scope read:durable; else True iff a `BookOpeningRecord(user,book)` exists. Note it uses `user_has_scope`, which returns True for any staff user for every scope, including both READ_ONCE and READ_DURABLE, so staff (non-superuser) are never limited (read_once True, durable True -> False).
- `user_can_download_book_assets`: scope download:file (book-aware) or owner.
- `user_can_view_preview_html`: owner True; read-once-limited False; else scope preview:html.
- `user_can_send_to_kindle`: scope send:kindle or owner.
- `user_can_launch_reader`: owner True; read-once-limited False; else any of preview:html, read:durable, download:file, read:once.
- `user_can_view_book_cover`: = user_can_launch_reader.
- DRF classes: `ScopePermission` (superuser/staff pass; `allow_book_scoped` makes has_permission True for all authenticated and defers to object permission; otherwise requires scope globally via user_has_scope with book None); subclasses `CanManageAccess` (access:manage), `CanManageProcessing` (processing:manage), `CanEditMetadata` (metadata:edit, book scoped), `CanViewPhysicalBooksList` (physical_books:view); `IsSuperAdmin` (authenticated and is_superuser).
Usage in my files: `IsSuperAdmin` -> RegisterView(unrouted), managed users list/create/detail/resend, access grants list/create/delete, access references. `user_can_view_book_cover` -> download cover. `user_has_read_once_limit`/`user_owns_book`/`user_can_view_preview_html` -> download html. `user_can_download_book_assets` -> other asset types (epub etc.). `user_can_send_to_kindle` -> send-to-kindle. `user_can_launch_reader` -> reader-launch. `user_has_scope(... SEND_KINDLE)` -> ProfileUpdateSerializer (kindle emails need Send to Kindle scope; global only; staff/superuser pass). `ensure_book_reader_access` (shared.py:237) -> reading-session, bookmarks, highlights slug endpoints. `CanManageAccess/Processing/EditMetadata/PhysicalBooks` are not used in these files (used by other apps; not verified here).
`capability_scopes` (User): superuser gets a fixed list of 12 scopes (not including every PermissionScope? includes submit:create, preview:html, read:durable, download:file, metadata:edit, physical_books:view, processing:manage, access:manage, source_records:view, admin:full_control, send:kindle, read:once); others get {"submit:create"} plus all active grant scopes of ANY target (global, book, category, contributor are all included, so UI capabilities can overstate global rights). `global_grant_scopes`: superusers return []; others sorted distinct global scopes (prefetch attr supported).
Scope enumerations: ACCOUNT_MANAGEABLE (10): access:manage, processing:manage, source_records:view, metadata:edit, physical_books:view, read:once, send:kindle, read:durable, preview:html, download:file. SCOPED (6): metadata:edit, read:once, send:kindle, read:durable, preview:html, download:file. Not manageable via UI: submit:create, admin:full_control.
Grant handling `sync_global_grants(user, scope_values, actor)`: deletes (hard) global grants of manageable scopes not in the new set (regardless of active/expired), then creates a grant (notes "Managed from the user administration workflow.", granted_by actor) for each scope not already active; existing but expired/inactive grant of a kept scope is not deleted, so it stays and a new one is added (duplicates).
Role model: superuser (all), staff (bypass user_has_scope and ScopePermission), grant-based scopes, ownership (`UserBook`).

## 5. Reader, preview, download, Kindle, bookmark, highlight, notes, progress

### 5.1 Reader launch and token endpoints
Reader launch (`POST books/<slug>/reader-launch/`):
1. Book by slug (path converter, slashes allowed) else 404.
2. If not superuser and not owner and `user_has_read_once_limit` -> 403 "You have already opened this book under the Read Once permission."
3. `allowed = user_can_launch_reader`; `session = get_active_preview_session(user, book)` (latest unexpired). If neither allowed nor a live session -> 403 "You do not have reader access for this book."
4. Read-once recording: if not superuser, not owner, has read:once (book-aware), and not read:durable -> `BookOpeningRecord.get_or_create(user, book)` (recorded at launch, once per user+book; permanent; there is no reset path except deleting the grant swap or record). Staff (non-super) pass user_has_scope for both and therefore never get recorded.
5. Create `PreviewAccessSession(user, book)` if none; `launch_count += 1`; `expires_at = now + 2 hours` (default_preview_expiry) refreshed on every launch; token = `secrets.token_urlsafe(32)`, unique, max 128.
6. Response `{launch_url: FRONTEND_BASE_URL + "/reader?manifest=" + urlquoted manifest_url, manifest_url, expires_at}`. manifest_url from `public_api_url` (uses `PUBLIC_API_ORIGIN` unless loopback; else `request.build_absolute_uri`; else path).
Read-once semantic gap: the second launch is blocked, but while the 2-hour session is alive the guard `user_has_read_once_limit` still fires first (an opening record exists after the first launch) so a user cannot even relaunch within the live session (step 2 comes before step 3's live session reuse), but existing token URLs keep working until expiry; session expiry is extended only by launch (not by use).
Token endpoints (manifest, epub, html) are AllowAny: the possession of the token is the credential (unguessable 256-bit). `get_token_preview_session`: 404 "Reader session is unavailable." if unknown or expired. No check that the user is still active, still has the scope, or the grant is revoked. Guest sessions (user null) are supported by the model/endpoints (user nullable) but nothing creates them in these files.
Manifest (`GET reader/<token>/manifest/`): requires an EPUB asset row (404 "EPUB asset is unavailable." if none); if not available on disk -> missing-asset flow. Returns `{book:{title,slug}, epub_download_url, html_preview_url ("" if no html asset or unavailable), reading_session_url, bookmarks_url, highlights_url, reading_session, bookmarks[], highlights[]}`; when session has a user, ensures a ReadingSession row (get_or_create with preview_session default) and inlines all bookmarks and highlights; guest sessions get empty urls. no-store headers (Cache-Control "no-store, no-cache, must-revalidate, max-age=0", Pragma "no-cache", Expires "0"). Also note `resolve_asset` is not used for EPUB here, so it can pick any status (`.first()` ignoring ready).
EPUB (`GET reader/<token>/epub/`): `resolve_asset` (READY only, else 404); not available -> missing flow; streams FileResponse inline (as_attachment False), filename `<safe title>.epub`, no-store. Sub-resource `epub/<asset_path>`: URL-decoded, backslashes to slashes, leading slashes stripped, rejects empty or any `..` segment (404), reads the zip entry (whole file read into memory every call), content type via mimetypes else application/octet-stream, no-store; missing entry 404, bad zip 404. No size limit; zip-bomb not considered. The route `epub/<path:asset_path>` has no trailing slash while the plain one has; order in urls puts the path route first.
HTML (`GET reader/<token>/html/`): READY html asset, normalized (5.3), no-store, content type from asset or text/html.
Reading session by token (`GET/POST reader/<token>/session/`): IsAuthenticated and `session.user_id == request.user.id` (else 403 "This reader session does not belong to your account."; unauthenticated 403 by DRF/or PermissionDenied "Sign in is required..."); guest -> 403. GET returns ReadingSession (created if absent). POST partial update of `last_location` (<=255) and `progress_percent` (float, no range validation 0-100); serializer.save(user, book, preview_session=session) rebinding. no-store.
Bookmarks by token: GET list (no pagination), POST create (fields location (required, <=255), label, note, chapter_href, chapter_label, preview_text (<=280)); unique (user, book, location): duplicate location -> DRF unique validator (serializer lacks user/book fields so validator not generated => IntegrityError 500 risk, see bugs). DELETE `<uuid>` own only (404 else), 204. no-store.
Highlights by token: GET list, POST create (cfi_range <=1024 required, chapter_href, chapter_label, text required, note, color in yellow|green|blue|pink|underline default yellow, kind highlight|quote default highlight, tags list of unique trimmed strings, empties dropped, null or "" -> []), PATCH partial (any of these including cfi_range/kind), DELETE. no-store.

### 5.2 Download (`GET books/<slug>/download/<asset_type>/`)
Asset type is a `slug` path converter compared against `GeneratedAssetType` values (cover, html, epub, others). Rules:
- cover -> `user_can_view_book_cover` (= can launch reader).
- html -> if not superuser/owner and read-once-limited -> 403 "You have already opened..."; `user_can_view_preview_html`; if allowed and not superuser/owner and holds read:once without durable -> record BookOpeningRecord (so downloading html under read-once consumes the single open; and a user could first call reader-launch).
- anything else (epub, etc.) -> `user_can_download_book_assets` (download:file or owner); no read-once recording.
- not allowed -> 403 "You do not have download access for this book."
- `resolve_asset` READY else 404; unavailable file -> missing flow; html -> normalized HTML response (not attachment, no no-store header here); everything else FileResponse `as_attachment=True` (for non-HTML) filename `<safe_title><ext>`; cover is therefore sent as an attachment (not inline) even though it is for display. No Cache-Control set on slug downloads (private data cached by browsers/proxies possible). No audit log.
- Filename: `safe_download_stem`: `re.sub(r'[<>:"/\\|?*]+', "-", value).strip().strip(".")`, empty -> "book". Suffix: EPUB ".epub"; HTML ".html"; COVER source suffix or mimetype guess or ".jpg"; others source suffix or guess or "".
- Non-ASCII (Bangla) titles go into Content-Disposition via Django FileResponse (RFC 5987 filename*), OK.

### 5.3 Preview HTML normalization (`access/services/preview_html.py`)
`normalize_preview_html(book, asset)`: reads bytes, decodes UTF-8 with `errors="replace"`, BeautifulSoup(html.parser). Calls `normalize_preview_book_sections(soup, dedication_html=book.dedication_html)`: finds `div.main-content`, `div.container`, anchor = main-content or `div.toc-section`; promotes leading front matter into the "book info" block (`promote_leading_front_matter`), splits leading front sections out of main content (`split_leading_front_sections`) and inserts each as `div.front-section` (h2 `front-section-title`) before main content; creates `div.book-info-section` titled "বই তথ্য" if absent; normalizes dedication (`normalize_dedication_heading_and_content`) either in an existing `div.dedication-content`/`h2.dedication-title` or inserts a new `dedication-section` before anchor (or appends to container/body). Titles are interpolated into an f-string of HTML unescaped (see bugs). Images: for every `<img>` whose src is local (no scheme/netloc, not starting "/" or "#", non-empty path) it resolves a file in the HTML asset's directory by file name, then by stem match (sorted iterdir), then, if the tag is a cover reference (class `cover-image`, alt contains "cover", or stem `book_cover`/`book_image`) the cover asset path or `book_cover.*`/`book_image.*` in the directory; inlines it as a base64 data URI (mime from extension, default image/jpeg). Returns the new HTML only if anything changed (`soup.decode()`), otherwise the original decoded text. Reads the entire file and images into memory per request; no caching. Only works when the asset is on local disk (`local_asset_path`); with remote storage images are not inlined and `source_path` is None.
HTML is served raw (no sanitizing, no CSP header added here; scraped content with scripts would execute in the API origin when opened directly). Important XSS surface.

### 5.4 Send to Kindle (`POST books/<slug>/send-to-kindle/`)
1. Permission `user_can_send_to_kindle` (send:kindle book-aware or owner) else 403 "You do not have permission to send this book to Kindle."
2. Recipient list: `user.kindle_emails` filtered through `validate_kindle_email_address` (strip, lower, Django validate_email, domain must be exactly `kindle.com`; message "Enter a Kindle email ending in @kindle.com."; subdomains such as `free.kindle.com` rejected). None valid -> 400 "Add at least one Kindle email in your profile before sending."
3. EPUB: `resolve_asset` (READY else 404); unavailable -> missing flow.
4. Read whole epub into memory; filename as 5.2.
5. Sender: `ACCOUNT_INVITE_FROM_EMAIL` or `DEFAULT_FROM_EMAIL`, quotes stripped, address part of parseaddr (fallback raw).
6. Backend: if `EMAIL_BACKEND` is `anymail.backends.brevo.EmailBackend` then forced to SMTP (Brevo API cannot attach EPUB) using EMAIL_HOST, _PORT (default 587), _HOST_USER, _HOST_PASSWORD, USE_TLS (default True), USE_SSL (False), TIMEOUT (20); else uses configured backend (default console). If SMTP and any of host/user/password empty -> 502 with long explanation and `failedEmails`, `senderEmail`.
7. Send one message per address on a single connection: subject = book title, empty body, attachment `application/epub+zip`. On `SMTPAuthenticationError` mark auth failure, push remaining addresses to failed, stop. Other exception: that address failed, continue.
8. If none delivered: 502 with detail (auth hint if SMTP auth failed, else generic) plus failed list. Otherwise records `UserBookKindleSend` (delete existing for user+book, create new, i.e. last-sent timestamp; model in catalog) and returns `{detail: "Sent to N Kindle email(s)." [+ " M delivery attempt(s) failed."], deliveredEmails, failedEmails, senderEmail}`.
No rate limit, no size check (Kindle limit 50 MB not enforced), synchronous in the request, and no read-once involvement.
Profile Kindle setup: see 5.5.

## 7. Text and URL utilities (`common/text.py`, `url_utils.py`, `epub_utils.py`)

`clean_display_text(value)`: falsy -> ""; `re.sub(r"\s+", " ", str(value)).strip()`.
Constants: `TRAILING_ENTITY_CLOSERS = {")":"(", "]":"[", "}":"{"}`; `ENTITY_EDGE_PUNCTUATION = " \t\r\n-:ঃ–—|/&,;.\"'“”‘’"` (includes Bengali visarga ঃ).
`clean_entity_display_text(value)`: clean_display_text then strip ENTITY_EDGE_PUNCTUATION from both ends; empty -> "". Loop 1: while last char is a closer and `count(closer) > count(opener)` (unbalanced extra closer) remove it, re-clean and strip edges (breaks when balanced). Loop 2: while first char is an opener and `count(opener) > count(closer)` remove it likewise. Returns the cleaned text only if `normalize_catalog_text(cleaned)` is non-empty (letters/numbers/marks present), else "". Note the strip in loop 1 may remove a trailing legit dot/comma after removing the paren.
`_is_textual_slug_character(ch)`: Unicode category starts with L, N or M (letters, numbers, marks; thus keeps Bengali combining vowel signs and virama).
`_collapse_separators(value, sep=" ")`: collapse runs of sep and strip sep from both ends.
`normalize_catalog_text(value)`: falsy -> ""; `unicodedata.normalize("NFKC", clean_display_text(value)).lower()`; per char: whitespace -> " ", L/N/M kept, everything else DROPPED (no replacement by space, so "a-b" becomes "ab", "O'Brien" -> "obrien", "ZWJ/ZWNJ" (category Cf) are dropped, which changes Bengali conjunct forms for comparison); then collapse spaces. No transliteration, no case folding beyond lower() (not casefold), no handling of Bengali ড়/ড় decomposition beyond NFKC (NFKC composes? NFKC does not recompose ড + ় into ড়; Unicode excludes it from composition, so both forms stay distinct unless canonically decomposed; NFKC yields the decomposed form for U+09DC, hence both inputs normalize to the same decomposed string; fine).
`unicode_slugify(value)`: falsy -> ""; NFKC lower; chars L/N/M appended; chars in {" ", "-", "_", "/", "|", ":", "–", "—"} become a single "-" (only when slug non-empty and previous not separator); every other char is dropped silently; finally collapse "-" and strip. Not unique-guaranteed; collisions handled elsewhere (not in my files).
`public_api_url(viewname, kwargs, request)`: `reverse()` path; `PUBLIC_API_ORIGIN` setting (rstrip "/"); if set and not loopback (localhost, 127.0.0.1, ::1) -> `urljoin(origin + "/", path.lstrip("/"))`; elif request -> `request.build_absolute_uri(path)`; elif origin set (loopback) -> joined; else the bare path.
`normalize_frontend_base_url(base_url)` (accounts/serializers/support.py:90-114): rstrip "/"; if hostname lowercased is localhost/127.0.0.1, no explicit port in URL and `FRONTEND_PORT` setting non-empty and not the default port for the scheme (80 http, 443 https) then rewrites netloc to `host:FRONTEND_PORT` preserving credentials. Used for both the configured FRONTEND_BASE_URL and the request-derived `protocol://domain` URL. `use_https = request.is_secure() or FRONTEND_BASE_URL.startswith("https://")`. Link = `{frontend_base_url}{path}?uid={uid}&token={token}`; email context also gets `domain`/`site_name` = netloc of frontend URL.
EPUB builder `build_simple_epub(title, sections=None, language="en")` (used only for seeding/tests): zip with `mimetype` stored uncompressed first, `META-INF/container.xml`, `OEBPS/content.opf` (EPUB 3.0 package; identifier `urn:seed:<slug of title>` where slug = `re.sub(r"[^a-z0-9]+","-",title.lower()).strip("-") or "book"`; non-Latin titles all become "book"), `OEBPS/nav.xhtml` (toc), `OEBPS/text/chapter-N.xhtml` per section, default two chapters. Manifest items id `chapter-N`, `href text/chapter-N.xhtml`, `application/xhtml+xml`. Section body is NOT escaped (raw HTML); title and ids escaped. No `dcterms:modified` metadata (strict EPUB 3 validators would flag). No stylesheet.

## 9. Bugs, dead code, security issues, surprises

Security:
1. `config/settings.py:108` ships a default DEMO_USER_PASSWORD literal and `demo-login/` logs anyone in without credentials as a normal user with real grants possible: the demo user is an ordinary DB user, so any grants an admin gives (or `capability_scopes`) apply; GET with side effects; the hard-coded password default means if the demo account exists it is also loginable via `login/`. Demo login ignores `is_active`, TOTP and throttling.
2. `password-reset/` returns a distinct 404 for unknown/ineligible emails (user enumeration), while the throttle (5/hour/IP) is the only defense; `password-reset/validate/` and `confirm/` are unthrottled (token brute force is infeasible but unthrottled anyway).
3. TOTP: `2fa/confirm/` and login OTP verification are not rate-limited per user (only login endpoint by IP, 10/hour); `2fa/disable/` and `2fa/setup/` require no password or current OTP (a hijacked session can disable 2FA or re-enroll; `setup` while enabled creates a second device that makes `verify_token` use only `.first()` ordering undefined, causing flaky logins).
4. `TOTPSetupView` returns the raw secret in the response and nothing marks it single-use.
5. The reader token endpoints (manifest, epub, html) are AllowAny with the token as sole credential; tokens do not check current grants or user status, last 2 hours, are extended on every launch, and are present in `launch_url` query strings (`/reader?manifest=<url containing token>`), so tokens appear in browser history and server logs. Revoking a grant or Read Once policy does not revoke live tokens.
6. Slug download for html and the preview HTML endpoint serve scraped HTML unsanitized from the API origin (stored XSS vector if scraped content contains scripts); no CSP / `X-Content-Type-Options` in these views.
7. `user_has_scope` treats `is_staff` as a wildcard and also treats `admin:full_control` grants as satisfying any scope; `is_staff` users bypass read-once. Staff status can only be set via admin site / seed (managed-user serializers don't expose it).
8. PermissionGrant create allows account-level `admin:full_control` / `submit:create` scopes through the API (not in the UI list) since only target-bearing grants are scope-restricted; `admin:full_control` then acts as a wildcard in `user_has_scope`. Also any grant `expires_at` can't be changed later.
9. Profile image upload has no type, size, or content validation; files stored under MEDIA and URL returned absolute; SVG upload would be served as an active content type.
10. `ManagedUserDetailView` allows editing/deactivating/changing the password of OTHER superusers (only delete is blocked); `PermissionGrantListCreateView` check blocks only self-targeted grants (a superuser can still grant to another superuser, harmless).
11. Hard-coded E2E credentials in the seed command and a production-unsafe seed (clears cache, deletes all CatalogCurationRun, resets processing data) without an environment guard. `source_site_batch_audit --cookie-header` accepts a live production session cookie on the command line.
12. Login CSRF: AllowAny login not CSRF-protected (DRF session auth only enforces CSRF for authenticated sessions).
13. Download endpoints do not set no-store (private ebook files cacheable); only the reader-token endpoints do.
14. Reset-link handling: `PasswordResetConfirm` uses only min length 12, no Django password validators (inconsistent with profile change).

Bugs and logic gaps:
- `ManagedUserCreateSerializer` has `global_scopes` as a plain declared field (`required=False`) but `User` has no `global_scopes` attribute; serializer.data after create may raise AttributeError or be omitted: DRF `ListField` read from instance via `get_attribute` -> `AttributeError` handled with `required=False`?? DRF skips the field when attribute missing and field is not required (SkipField), so output omits it; verified by reading logic, not executed.
- `SavedFilter` create: serializer excludes `owner`, so DRF's unique_together validator is dropped; a duplicate (owner,target,name) raises IntegrityError, a 500. Same for `Bookmark` duplicate `(user, book, location)` (serializer has no user field): 500 on duplicate bookmark location rather than 400. `Highlight` has no unique constraint.
- `ReaderLaunchView`: read-once check occurs before reuse of an active session, so a read-once user cannot re-enter even within the live 2-hour session after the first launch (the opening record is created on first launch). Likewise `BookAssetDownloadView` html for read-once records an opening on first html download, consuming the single read. The record is never cleared when a user's grant is changed from read:once to durable (the limit simply stops applying) or back (the old record then blocks immediately).
- `user_has_read_once_limit` and several rules rely on `user_has_scope`, which returns True for all scopes for staff: staff ignore read-once even though `is_superuser` is explicitly excluded elsewhere.
- `ensure_book_reader_access` does not allow owners (`user_owns_book`) while `user_can_launch_reader` does: owners without grants get 403 on bookmarks/highlights/reading-session slug endpoints unless a live preview session exists.
- `ReaderManifestView` picks an EPUB asset with `.first()` ignoring `status`, whereas epub download uses READY only; can reference a FAILED asset (but asset_is_available is checked after `clear_missing_asset` which marks FAILED).
