## Normalisation trace

Two different normalisers exist and are used in different places (inconsistency, see Findings).

### N1 `normalize_catalog_text` (A/common/text.py:53-66) - the persisted key
Used for `Book.normalized_title` (catalog/models/books.py:97 `self.normalized_title = normalize_catalog_text(self.title)`), contributor/series/category `normalized_name` (catalog/services.py:60-100), and every set comparison in detection.py.
Steps: `clean_display_text` (collapse whitespace, :5-8) -> NFKC -> `.lower()` -> keep a char only if whitespace (becomes " ") or Unicode category L*, N*, M* (:63-64, :43-45) -> collapse spaces.
Consequences (derived from code):
- All punctuation and symbols are DELETED, not replaced by a space. Hyphen, danda "।", quotes, "(", ")" vanish. "রবীন্দ্র-নাথ" -> "রবীন্দ্রনাথ" but "রবীন্দ্র নাথ" stays two tokens, so they differ. "কপালকুণ্ডলা (উপন্যাস)" -> "কপালকুণ্ডলা উপন্যাস".
- ZWJ/ZWNJ (category Cf) are deleted. Good for Bengali conjunct variants (e.g. "র‍্যাব" == "র্যাব"), since ZWNJ/ZWJ are not L/N/M.
- NFKC decomposes the nukta letters ড় ঢ় য় (U+09DC/09DD/09DF are composition exclusions), so precomposed and base+nukta forms compare equal. Combining marks (vowel signs, hasanta, nukta) are kept (category M).
- Bengali digits are category Nd so kept as-is; "১৯৮৪" and "1984" are NOT equal in N1 (NFKC does not fold Bengali digits to ASCII).
- No spelling normalisation: ি/ী, ু/ূ, ণ/ন, শ/ষ/স, ৎ/ত্, জ/য, hasanta order, "রবীন্দ্রনাথ ঠাকুর" vs "রবীন্দ্রনাথ ঠাকুর" with different ordering all stay different. No transliteration, no honorific stripping ("ড.", "মো:", "শ্রী") in the key (only in `looks_like_contributor_name`, which rejects some).
- Latin letters are lowercased, so "Humayun Ahmed" == "humayun ahmed", but Latin and Bengali spellings of the same person never match.

### N2 `normalize_text` (A/ingestion/pipeline/scraper_support/text.py:5-25)
Same as N1 except the whitespace collapse uses `re.sub(r"\s+"," ")` and there is NO `clean_display_text` pre-pass (immaterial). Used for `texts_are_similar`, resolver scoring, and `SourceCatalogEntry.normalized_title` (resolution_support_metadata.py:41). Functionally equal to N1 for practical input.

### N3 `extract_core_title` / `normalize_bengali_numbers` (text.py:28-103) - fuzzy helpers
- `extract_core_title` (:79-103): normalise via N2, split on spaces, cut the title at the first token (index > 0) that CONTAINS any of the "author indicators" `["লখক","অনবদক","সমপদক","রপনতর","মল","অনবদ","রচন","সকলন"]` (:85-94). These literals are written WITHOUT vowel signs/hasanta (e.g. "লখক" = ল-খ-ক, a mangled "লেখক"). Real "লেখক" normalised by N2 keeps ে, so it is "লেখক", which does NOT contain the substring "লখক" (the ে sits between ল and খ). So the indicator list almost never matches real Bengali text, except accidentally as substrings of unrelated words (e.g. "মল" is a 2-letter substring: matches "মলাট", "কমল", "বিমল", "কমলা", "মলয়"). I derived this from reading the literals; I did not run it. NOT VERIFIED BY EXECUTION.
- `normalize_bengali_numbers` (:28-76): returns variants: normalised text; Bengali digits->ASCII; and for each ordinal word ("প্রথম"->"1ম" etc.) a variant replacing the word with digit form. Note the replacement strings are ASCII digit + Bengali suffix ("1ম", "2য়"), so they only match titles that literally write "1ম"; a title written "১ম" is converted by step 2 to "1ম" - OK that path works. Replacement is `str.replace` over substring, so "প্রথমা" (a name/title) is also altered ("1মা") in the variant - false-positive vector.

### N4 Contributor extraction pipeline (normalization_support/metadata.py + scraped_book_normalization.py)

1. Front-matter HTML = `combined_front_matter_html(book_info, main_content)` (:225-228) -> `extract_role_contributors` (:242) -> contributors with explicit role labels (translator, editor, publisher, illustrator, cover artist, compiler).
2. Then the scraped `author` string is parsed with `extract_contributor_evidence(author, raw_value=author)` (:245-248). Labelled parts in it become role contributors (:249-250); unlabelled names become `authors` and are added with role AUTHOR unless the same normalised name was already claimed by a non-author role (:252-267).
3. `normalize_book_contributors` (catalog/services.py:34-60) dedups by (normalised name, role) and drops any AUTHOR entry whose name also appears under a non-author role.
4. `series` = `split_multi_value(series)`, `categories` = `split_multi_value(book_type)` (:272-273). `split_multi_value` (metadata.py:554-567) splits on `[,;|\n]` ONLY, cleans edge punctuation (`ENTITY_EDGE_PUNCTUATION`, common/text.py:16), dedups by N1 key.
Name splitting (`split_contributor_chunks`, metadata.py:813-871): split on `,;|\n`, then on connector pattern ` ও | and | & ` (:92) ONLY if every part passes `looks_like_contributor_name` (:857-862), else keep the whole chunk as ONE name. E.g. "হুমায়ূন আহমেদ ও জাফর ইকবাল" -> two authors; "অনিল ও শিউলি" (a part under 3 chars? no, "ও" splits) depends on the validator.
Name validator `looks_like_contributor_name` (metadata.py:623-770) rejects (non-publisher roles): any digit (:635), <3 non-space chars (:638), month names (:641-651), "।!?" (:652), colon/ঃ except "মো:" prefix (:654-659), address fragments (:660, :526-551), NON_PERSON_TITLE_WORDS tokens (:103-135, :666) e.g. "সমগ্র","গল্প","ইতিহাস" as a token, `NON_NAME_PHRASE_WORDS` (:136-154, includes the real-name token "সব্যসাচী" at :148 -> any author named "সব্যসাচী ..." is rejected), publisher keywords (:676) e.g. a person whose name contains "লাইব্রেরি", leading tokens like "ডক্টর","অধ্যাপক","ডঃ","ডা.","জনাব" (:274-277, :702-703) -> "ডক্টর মুহম্মদ শহীদুল্লাহ" is REJECTED entirely rather than stripped, tokens ending in verb suffixes "বেন","ছেন"... (:314-318, :710-713; "বেন" is a suffix of many words and surnames e.g. "রবেন"? any token ending "বেন"), any token containing "." unless initials pattern `^(?:[A-Za-zঀ-৿]{1,4}\.)+$` (:759-765, :93), >80 chars or >8 words (:766-769).
Net effect: author strings failing the validator produce NO author, which downstream makes the book unmatchable (see rules below).

## Matching/duplicate rules trace with thresholds
(Complete list of "same book" checks. All thresholds are string lengths or set intersections; there is no edit distance, no token-set ratio, no numeric similarity score in catalog matching.)

### R1 `texts_are_similar(t1, t2)` (text.py:106-168) - fuzzy title equality, cascade, first hit returns True
1. N2(t1) == N2(t2) (:118).
2. Both normalised strings length > 10 chars AND one is a substring of the other (:123). 10 is a character count (Bengali conjuncts are several code points; ~5-6 visible letters).
3. `extract_core_title` of both: both non-empty and both len > 5; equal, or one contained in the other (:128-138). Core cut is erratic (see N3).
4. All variants from `normalize_bengali_numbers`: any pair equal, or both > 10 chars and one contains the other (:140-155).
5. For each prefix in `["লখক","অনবদক","সমপদক","মল"]`: remove ALL occurrences of the prefix as a substring from both normalised strings (:159-160) and compare equality (:161). Because replace is global and "মল" is a common substring, this deletes "মল" inside words ("কমল"->"ক", "বিমল"->"বি").
Not a ratio; no Levenshtein. Returns bool.
Worked examples (derived by hand, not executed):
- "পথের পাঁচালী" vs "পথের পাঁচালী (উপন্যাস)": N2 -> "পথের পাঁচালী" vs "পথের পাঁচালী উপন্যাস"; lengths 12 and 20 > 10, substring -> TRUE (rule 2). Same book; correct.
- "দেবী" vs "দেবী চৌধুরানী": shorter is 4 < 10, rule 2 fails; core titles: "দেবী" len 4 not > 5 -> rule 3 fails; rule 4: first variant lengths fail; rule 5 no. -> FALSE. Distinct works here; but also means a short true title plus subtitle does not match (false negative, e.g. "গোরা" vs "গোরা উপন্যাস").
- "আনন্দমঠ উপন্যাস সমগ্র খণ্ড ১" vs "আনন্দমঠ উপন্যাস সমগ্র খণ্ড ২": N2: both ~26 chars, neither is substring of the other (differ in last digit) -> rule 2 false. Core title: no indicator tokens except accidental -> if equal cores then TRUE. Rule 4: digit variants "…খণ্ড 1"? bengali digits converted to ASCII, still differ. Likely FALSE. But "সমগ্র" volume 1 vs "সমগ্র" volume 10: "…খণ্ড ১" vs "…খণ্ড ১০" -> shorter is a SUBSTRING of longer, both > 10 -> TRUE (rule 2). FALSE POSITIVE: volume 1 matches volume 10..19, "ভাগ ১" matches "ভাগ ১২".
- "কমলাকান্তের দপ্তর" vs "বিমলাকান্তের দপ্তর": no. Skip.
- Containment false positive: "রবীন্দ্র রচনাবলী" (16 chars) is a substring of "রবীন্দ্র রচনাবলী দ্বিতীয় খণ্ড", so every volume matches every other volume's title that embeds the series name (volume vs set).
- Different works with common long title fragment: "পদ্মা নদীর মাঝি" vs "পদ্মা নদীর মাঝি ও অন্যান্য গল্প" -> TRUE (substring). A collection containing the novel is treated as the same book.

### R2 `find_exact_existing_book(scraped)` (detection.py:83-129) - used in both submission and processing paths
Candidate set: `Book` with `source_site == get_source_site_domain()`, `normalized_title == N1(title)` (exact equality, indexed), not soft-deleted, newest first (:89-101).
Requires target authors non-empty AND target categories non-empty (:109-110), else returns None.
For each candidate (:112-127): skip unless candidate has authors and categories; require CATEGORY set intersection non-empty (:120); if target has series, require series intersection (:122); if target has translators, require translator intersection (:124) (candidate with no translators fails when target has some); require AUTHOR intersection non-empty (:126) -> return book.
All comparisons are exact N1 string equality of full names, set intersection (>=1 shared). No threshold.
So "same book" = same N1 title + >=1 shared author name + >=1 shared category + series/translator constraints.

Caveat: if target has no translators but the candidate has, the check is skipped and it IS flagged duplicate (asymmetric): a translated edition vs the original-language edition of same title+author+category are flagged duplicate.

### Duplicate vs new edition, as the live code behaves
- Live path (see submission path) uses R2 then R3 only. Edition and publisher are not compared. Two editions by different publishers of the same title/author/category => duplicate. Two editions with different translators (both having translators) => R2/R3 treat as NOT duplicate (translator intersection empty) => becomes a new Book, so "different translator = new edition" is implemented implicitly via set intersection only.
- Missing author or missing category on either side => no duplicate found (R2 :109/:118; R3 :67/:69) => a new Book is created even if the title is identical. Author-parse failure (validator rejections above) therefore yields a duplicate Book rather than a conflict.
- `find_deleted_book_by_title` (catalog/services.py:135-148): N1 title + source_site + soft-deleted, newest `-deleted_at`. NO author check. Used in `persist_scraped_book` (persistence.py:91): a new submission whose title equals a deleted book's title RESURRECTS that deleted Book row (deleted_at cleared, content replaced, persistence.py:79-95) even if the author differs. False positive: delete "আশা" by author X, later submit "আশা" by author Y -> overwrites the deleted record; MetadataVersion (:132) keeps history but the Book id/slug/catalog code are reused.
- `find_existing_book_by_source_url(normalized_source_url)` (catalog/services.py:151-158): lookup via BookSource.normalized_source_url on live books; used only after an IntegrityError on Book create (persistence.py:110-120) - a race/uniqueness fallback, not a primary match.

### Where false positives / negatives occur (summary of derived cases)
FP: R1 substring rule (volume 1 vs 10, collection vs component, series prefix); `find_deleted_book_by_title` author-blind resurrection; "মল" global strip in R1 rule 5; ordinal-word replace inside names.
FN: any spelling variant (ি/ী etc.), hyphen vs space, Bengali vs Latin name, honorific differences ("ড. X" vs "X"), differently ordered multi-authors are fine (set) but "X ও Y" parse failures; author validator rejection => no author => no match; missing category => no match; short titles (<= 10 chars) with a subtitle; title in R2 requires exact N1 equality (not fuzzy) so "রবীন্দ্র-নাথ" etc.
Asymmetric translator handling noted above.


## Resolution trace (title query -> source URL; A/ingestion/services/resolution*.py)

Entry: `TitleResolver.resolve(query, refresh_catalog)` (resolution.py:239). Called by `resolve_submission` (resolution_and_queueing.py:85) with `submission.original_input`.
1. `normalized_query = normalize_text(query)` (N2, :240).
2. `collect_candidates` (:196-212): loads EVERY `SourceCatalogEntry` row (`objects.all()`, :198), scores each in Python, keeps confidence > 0, top 3 by score.
3. Score `score_candidate_fields` (:137-154): 1.0 if N2(title)==query or N2(title+" "+author_line)==query; else 0.88 if `texts_are_similar(query,title)` (R1); else 0.78 if query is a substring of title or vice versa (no length floor - a 1-3 character query matches many titles at 0.78); else Jaccard of token sets (title+author vs query) * 0.75, rounded to 3 dp. Hence max non-exact score is 0.88; only 1.0 can produce `exact_match`.
4. If no candidates, or `refresh_catalog=True`, call `refresh_catalog(max_pages=None, bucket=derive_bucket(query))` (:244-258): crawls the source site's `/books/` archive filtered by first letter (`_a_z` param, :123-135), paging until a page repeats its first 5 URLs (:104-107) or is empty; upserts `SourceCatalogEntry`. Errors are swallowed into `raw.refresh_error` (:252-257).
5. Top 3 are enriched by fetching each candidate's own page (`fetch_source_page_metadata`, :214-237) - up to 3 live HTTP GETs per resolution; exceptions silently ignored (:232). Confidence can only go up (`max`).
6. Decision (:267-294): `exact_match` iff top confidence == 1.0 and (no second or second < 1.0); `ambiguous` if any candidates otherwise (resolved_url empty); else `unresolved`. Two entries scoring 1.0 (same title, two authors/editions) => ambiguous.
Title/author split of the site's display string `split_display_title` (resolution_support_metadata.py:80-91): split at " – | — | - " (surrounded by spaces); from the right, the first suffix that `trailing_looks_like_contributor_phrase` (:53-77; no digits, <=140 chars, max one sentence mark, none of the NON_CONTRIBUTOR_TITLE_SUFFIXES substrings, and `extract_contributor_evidence` yields a contributor/author) is the author line. Titles with a dash and a name-like tail get split; titles like "A - B" where B looks like a name are mis-split.
Candidate -> submission: `resolve_submission` (resolution_and_queueing.py:85-127) stores a `TitleResolutionAttempt` + up to 3 `MatchCandidate` rows; exact_match => `resolved_url` set, status QUEUED; ambiguous/unresolved => `NEEDS_REVIEW`, review_state NEEDS_REVIEW; the user confirms a candidate via `SubmissionConfirmCandidateView` (views/submissions.py:135-176).

### Network / DNS behaviour (resolution_support_network.py, resolution.py:36-69)
- `get_with_host_fallback` (network.py:241, duplicated in resolution.py:36): try the URL's host, then `SOURCE_SITE_HOST`, then `SOURCE_SITE_FALLBACK_HOSTS`; only on ConnectionError whose text contains "name resolution"/"gaierror" (hosts.py:75-76) move on. Then for each host, `resolve_host_with_dns_fallback` (:158-188): system `getaddrinfo`, then raw UDP DNS A-queries to each resolver in `SOURCE_SITE_DNS_RESOLVERS` (default 1.1.1.1, 8.8.8.8, hosts.py:41-49) on port 53 with hand-built packets (:64-116), then, only if nothing found, DoH: `GET https://1.1.1.1/dns-query` with `Host: cloudflare-dns.com` and `verify=False` (:119-155). Each resolved IP is then fetched directly over HTTPS with `assert_hostname=host`, `server_hostname=host`, `CERT_REQUIRED` (:203-238), so the origin certificate is still verified against the site hostname.
- DoH call has TLS verification disabled (`verify=False`, :131) against a literal IP, so the DNS answer can be forged by a network attacker; mitigated only because step above verifies the site cert. Failure is swallowed (`except Exception: return []`, :134-135).
- The whole stack exists to bypass DNS blocking of the source site (inference from fallbacks; the code gives no stated reason). In production this is user-agent-spoofed scraping (`SEARCH_HEADERS` is a fake Chrome UA, hosts.py:6-12).
- Host allow-list for catalog parsing: `_get_allowed_source_hosts()` (network.py, called resolution.py:167) and URL validation `normalize_source_url` (network.py:47-60): only http/https, host in allow-list, path must start with `/books/`; output forced to `https://<SOURCE_SITE_HOST>/books/.../` with query/fragment dropped. SSRF is restricted to the source site by this allow-list (the host passed to `validate_source_url` is allow-listed; empty allow-list => `if allowed` is falsy and ANY host passes, network.py:53 - behaviour depends on config; NOT checked what the config default is).

Else `capture_source_page_metadata` (live HTTP fetch of the book page, retry_and_deduplication.py:147-154, errors swallowed) and `find_existing_book_by_source_url`; hit => `fulfill_submission_with_existing_book` (status READY, linked_book set, `served_from_database`, preview session + AuditLog, resolution_and_queueing.py:47-82). Else RESOLVED, QUEUED.
Title entry (:64-95): reuse by `normalized_input` equality (exact N2 equality of the query text, not fuzzy); else `resolve_submission` (see Resolution trace; synchronous HTTP inside the request); if a URL came out, reuse/fulfil as above.
Finally if `auto_process` and a URL exists and status QUEUED => `queue_submission` (:97-98).
Observation: synchronous, request-thread network I/O (page fetch, catalog crawl up to the whole letter bucket, up to 3 enrich fetches) for every entry; errors in the title path other than those swallowed would 500 the whole batch (no try/except around `resolve_submission`).

### 3. `queue_submission` / `dispatch_processing_job` (resolution_and_queueing.py:130-204)
Root submission; if an active (queued/processing) job exists return it (:132-134). Else create `ProcessingJob(INGESTION, QUEUED, payload{resolved_url, actor_id})`, submission QUEUED, sync dependents, `dispatch_processing_job`. Dispatch: assign uuid `task_id`, queue "engine", `dispatch_job` (ingestion/engine/dispatch.py:14-35) which does Redis HSET `engine:job:handlers`, RPUSH pending queue and PUBLISH `CH_JOB_REQUEST`. If Redis dispatch raises: log, set queue_name "inline-fallback" and run `process_submission_job` INLINE in the request/caller thread up to `MAX_PROCESSING_JOB_ATTEMPTS`=3 times (:178-203) - a whole scrape+export inside the HTTP request when Redis is down.
Engine side: a listener thread in each Django worker process (ingestion/signals.py:120-160) receives `CH_JOB_ASSIGNED`, filters by hostname, and calls `process_submission_job(job_id, 0, "engine")` (handler "process_submission") or `kickoff_request_processing(job_id)` (handler "pipeline", signals.py:149-151). Note the "pipeline" handler passes a job id to a function that takes a BookCreationRequest id (type/semantic mismatch visible at signals.py:151 vs processing/service_modules/request_processing_pipeline.py:449; the dispatcher never emits handler "pipeline" in the files I read - NOT verified who does).
The older Celery task path also exists: ingestion/tasks.py:77 calls `process_submission_job` (A/ingestion/tasks.py NOT READ beyond grep).

### 4. `process_submission_job` (processing_job_runner.py:3-289) - state machine
Guards: SUCCEEDED/CANCELLED => return (:8-11); cancel_requested => finalize cancelled (:12-13). Sets job PROCESSING (retry_count, task_id, started_at), submission PROCESSING, sync dependents, log "Started processing" (:14-23).
Steps (cancellation re-checked between each via `cancel_requested_for_job` which `refresh_from_db`, :26,48,82,114):
1. Title with no URL: `resolve_submission(force_refresh=True)`; still no URL => job SUCCEEDED, submission left at NEEDS_REVIEW (set inside resolve_submission), log warning (:28-36). (Job "succeeded" without any book.)
2. `normalize_source_url`; REPROCESS: load target book, set `book.state=PROCESSING` (:39-46).
3. `capture_source_page_metadata` (live fetch; stored in `raw_payload.source_page_metadata`; also upserts `SourceCatalogEntry`) (:50-56).
4. Source-URL duplicate (skipped for reprocess or `raw_payload.skip_duplicate_checks`) => `fulfill_submission_with_existing_book` (READY), `DuplicateReview(CONFIRMED, detected_by exact_source_url)`, job SUCCEEDED with book (:57-80).
5. Scrape + curate: if `legacy_scrape_overridden` (test monkeypatch detection by `__module__`, :84-87) use `scrape_book`; else `curate_book_document(normalized_url, content_limits)` (:96-97). `high_fidelity` limits for reprocess. Log "Curated source content".
6. R2 exact-title duplicate => same as 4 with `detected_by exact_normalized_title`, CONFIRMED (:116-142). So: exact duplicate = silently satisfied, submitter gets READY + the existing book + preview session.
7. R3 fuzzy duplicate => submission `DUPLICATE`, review_state NEEDS_REVIEW, `duplicate_of_book` set, preview payload (title/author), `DuplicateReview(PENDING, normalized_metadata)`; job SUCCEEDED; **terminal for the submission** (:144-170).
8. Curated INVALID and no title => persist curated document, submission NEEDS_REVIEW with message, job SUCCEEDED (:172-192).
9. `persist_curated_book(...)` (curated_persistence NOT READ in detail; hooks `find_deleted_book_by_title`, `find_existing_book_by_source_url`, `replace_book_relations`) creates/updates the Book (resurrecting a deleted Book of the same title, see R-deleted above, via persistence.py:91 for the non-curated variant; the curated variant calls `find_existing_matching_book` at curated_persistence.py:329/363 - NOT READ).
10. If curated status != VALIDATED (non-legacy): submission NEEDS_REVIEW, linked_book set, no assets, job SUCCEEDED (:200-222).
11. Else `generate_exports` (HTML + EPUB) and `sync_assets` (HTML+EPUB are REQUIRED asset types, job_lifecycle.py:122), `complete_processed_submission` (persistence.py:8-44): linked_book, status READY, review_state = book.review_state, resolution RESOLVED, `served_from_database=False`, preview access session for the submitter (if any), AuditLog `submission.processed`; job SUCCEEDED with log (:224-246).
Exceptions (:247-289): `retry_count+1 < 3` => `requeue_processing_job` (submission QUEUED, error cleared, job QUEUED, log "auto_requeued") and **re-raise** so the worker sees failure and the engine/other layer redelivers (retry mechanics of the engine NOT READ); otherwise submission FAILED with `str(exc)` saved verbatim in `error_message` (raw exception text exposed to the submitter through the serializer? serializer NOT READ), reprocess restores `previous_book_state`, job FAILED, log error, re-raise.
Statuses are written to the root submission and mirrored to dependents by `sync_deduplicated_submissions` (sync.py:87-98) after every transition (N dependent saves per transition).

## Overlap with the processing path (BookCreationRequest)

Two parallel pipelines write the same `Book`:
- Submission path: user/operator-driven; entity `BookSubmission` + `ProcessingJob` (ingestion app). Input: URL or title. Job state in `JobStatus`; user-visible `SubmissionStatus`. Dispatched via Redis engine, "inline-fallback" otherwise.
- Processing path: catalog-sync/automation-driven; entities `BookRecord` (one per source URL, `url` unique, models.py:48-93) and `BookCreationRequest` (processing/models.py:96-165) with its own state machine INITIAL->QUEUED->PROCESSING->CREATED|FAILED|DUPLICATE|PAUSED|DELETED (models.py:13-21) and `advance_pipeline_once()` (request_action_dispatch.py:190-248: mark stale, move first QUEUED->PROCESSING (or enqueue), run first PROCESSING if inline/manual, move first INITIAL->QUEUED; one item of each state per tick). Retries: `MAX_PROCESSING_REQUEST_ATTEMPTS`=3 in-process loop with a 60 s sleep for "Incomplete scrape" (request_processing_pipeline.py:380-417) - blocking `time.sleep` in the worker. Operator actions: pause/resume/retry/force_generate/new/new_edition/confirm_duplicate/recreate/delete (request_action_dispatch.py:251-281).
Shared pieces: `find_existing_book_by_source_url`, `find_exact_existing_book`, `detect_metadata_duplicate` (processing/source.py:23-24 imports the same detection functions), `capture_source_page_metadata`, `upsert_source_catalog_entry`, `persist_curated_book` (+ `persist_scraped_book`), `generate_exports`, `sync_assets`, `export_payload_from_book`.
Differences:
- Duplicate semantics: processing path marks the request DUPLICATE (`_mark_request_duplicate`, request_processing_persistence.py:133-172) and an operator picks `new` (sets `is_confirmed_not_duplicate`, re-queues; apply_new_action :50-98), `new_edition` (creates/links a `BookGroup` of sibling editions, stores `target_book_group_id` in the submission payload :30-47), or `confirm_duplicate`. Submission path has no equivalent operator action (see dead-end above) and exact duplicates become READY.
- The fuzzy R3 check is SKIPPED by default in the processing path: `PROCESSING_SKIP_METADATA_DUPLICATE_CHECK` default True (checkpoint_and_runtime_adapters.py:225-228), used at request_processing_pipeline.py:37-38. In the submission path it always runs (processing_job_runner.py:144). So the same scraped book is classified differently depending on the route.
- Progress/resume: processing path checkpoints scraped data in `BookCreationRequest.progress` (PAUSED resume, request_processing_pipeline.py:66-92, :284-289) and a disk scrape cache with a heartbeat thread (:3-26, :232-249); submission path has no pause or checkpoint (cancel only).
- Review gate: processing path fails the request with "requires review" when curated status != VALIDATED unless `force_generate` (:315-320, request_processing_persistence.py:201-206); submission path sets NEEDS_REVIEW and has no force action.
- Edition handling: `apply_new_edition_action` is the only place a `BookGroup` is created for the processing path (request_action_dispatch.py:19-27); whether the submission path's `target_book_group_id` is ever consumed in persistence NOT verified (persistence.py:56-133 does not read it; curated_persistence NOT READ).
- Link between the two: `BookCreationRequest.submission` OneToOne (processing/models.py:151-157) exists and is read in `apply_new_edition_action` (request_action_dispatch.py:40), but I found no non-test code that sets it (grep `submission=` in processing/ returned nothing; `BookCreationRequest.objects.create` at automation_commands.py:13 and incomplete_resolution.py:30 pass no submission). So the "new_edition" group hint likely never reaches a submission in practice. Inference from grep; not executed.
- Origin: both carry `origin` (user|curation|automation). Catalog automation uses the SUBMISSION path (`create_submission_records` called from curation_modules/catalog_automation_runs.py:47 and views/catalog_entries.py:250) AND the processing path creates requests directly (`automation_commands.py:13`), so automation can enter either route.
Overlap risk: the same URL can be processed concurrently by a `BookCreationRequest` and a `BookSubmission`; the only guard is the `Book` create IntegrityError fallback by source URL (persistence.py:110-120) and the `BookSource.normalized_source_url` update_or_create (:123-131). No cross-path lock was found.

## Findings (severity, evidence)

HIGH
1. Fuzzy-duplicate submissions are a dead end: status DUPLICATE, DuplicateReview PENDING, retry re-runs same checks, `skip_duplicate_checks` never set, review status settable only in Django admin (processing_job_runner.py:144-170; retry_and_deduplication.py:157-203; admin.py:19). A genuine second edition with the same title/author/category cannot be created through submissions.
2. Live duplicate logic ignores edition: publisher/edition never compared in R2/R3 (detection.py:83-80 region); `classify_incoming_book` that would model new_edition is not called anywhere in non-test code (grep). Two editions by different publishers => treated as the same book => second never created or silently mapped to the first (exact path => READY linking to the old book, detection.py:112-127; processing_job_runner.py:116-142).
3. Missing author/category => no duplicate detection at all (detection.py:109-110, 67-70), combined with a very aggressive author validator that rejects names with honorifics ("ডক্টর", "ডঃ", "অধ্যাপক", "জনাব", "মৌলভী"), the token "সব্যসাচী", verb-like endings "বেন"/"ছেন", names with digits or '.' (metadata.py:136-154, 274-277, 314-318, 635, 759-765). Result: duplicate Books for the same title+author.
4. Deleted-book resurrection ignores author: `find_deleted_book_by_title` (catalog/services.py:135-148) used in persistence.py:91 overwrites a deleted record of a different book with the same N1 title (different author), reusing id/slug/catalog code.
5. Synchronous network and scraping in request threads: `create_submission_records` (resolution + page fetch) and inline fallback processing of a full scrape when Redis dispatch fails (resolution_and_queueing.py:178-203; book_persistence.py:38,74). Unbounded entries per POST for anonymous users (serializers/common.py:16-47; rate 40 requests/hour only, settings.py:215).

MEDIUM
6. `texts_are_similar` substring rules give false positives for volumes/series (e.g. "...খণ্ড ১" vs "...খণ্ড ১০") and false negatives for short titles (text.py:123, 130-138). The `extract_core_title` and prefix lists contain vowel-stripped literals ("লখক","অনবদক","সমপদক","মল") that look like a mangled-encoding bug and that match arbitrary substrings such as "মল" (text.py:85-94, 157; derived, not executed).
7. `detect_metadata_duplicate` full-table Python scan on every submission with 3 prefetches (detection.py:53-60): O(N) per job, no `source_site` filter, plus asymmetric translator rule (detection.py:75).
8. Divergent duplicate policy between the two pipelines (fuzzy check on in one, off by default in the other, request_processing_pipeline.py:37 vs processing_job_runner.py:144); duplicated helpers (`get_with_host_fallback` is defined twice, resolution.py:36 and resolution_support_network.py:241).
9. Title resolution scoring: any query that is a substring of a title scores 0.78 with no length floor (resolution.py:144-147); loads all `SourceCatalogEntry` into Python per resolve (:198); crawls an entire letter bucket of the live site (:244-258). Resolver key `exact_match` requires string-equal title (1.0), so titles with differing punctuation/hyphen handling (N2 removes punctuation) still reach 1.0 while "A – Author" form splitting can mis-split titles containing " - " (split_display_title).
10. `job.status = SUCCEEDED` is used for outcomes that are not successes: unresolved title (processing_job_runner.py:31-36), fuzzy duplicate (:166-170), curated needs review (:188-192, :217-222). Job status cannot be used alone to know whether a book exists.
11. Raw exception text stored in `submission.error_message` and `job.last_error` (processing_job_runner.py:265, 276); whether serializers expose it to anonymous submitters is NOT READ.
12. Revocation uses Celery (`current_app.control.revoke`) while dispatch uses the Redis engine (job_lifecycle.py:154-160 vs engine/dispatch.py:14); a cancel of a running engine job may not stop the worker (inferred; not run).
13. DoH lookup with `verify=False` (resolution_support_network.py:131); hand-rolled DNS packet parsing (:64-116); fake browser User-Agent (hosts.py:6-12). These are scraping-evasion mechanisms to remove in a rebuild.
14. Retry permission check uses the dependent's `submitter_id` rather than the root's (retry_and_deduplication.py:160).

LOW
15. `exec()`-concatenated "facade" modules (normalization.py:13-15; submissions.py:14-16): all names live in one namespace; undefined-name risk and no static analysis (the module fragments have no imports, e.g. processing_job_runner.py starts with a blank line and uses names from siblings).
16. Bengali ordinal replacement is substring-based and alters words like "প্রথমা" in comparison variants (text.py:70-74).
17. `classify_incoming_book` / `BookGroup` concept is the only edition model; it is mostly dead on the submission path.

## Keep / change / drop for a rebuild

KEEP (as concepts)
- Normalised-title key stored on the Book and indexed (N1 semantics: NFKC, lowercase, drop punctuation, keep letters/digits/marks) and author/translator/category as normalised name sets; but redefine them explicitly (see change).
- Duplicate verdict model from `classify_incoming_book`: exact_duplicate / new_edition / new_work / needs_review (detection.py:198-201). It is the right shape; wire it in and have a human resolve needs_review.
- Submission as a durable record with steps/log, root + dependent (dedup) submissions, reusable-submission lookup by resolved URL, source-URL uniqueness as the first and cheapest duplicate check, audit log events, job retry cap (3) and stale-job recovery, soft-delete then hard delete.
- Cancel flag checked between steps.

CHANGE
- Matching: use a staged matcher: (1) exact source-URL identity; (2) normalised-title equality plus author overlap; (3) fuzzy only as a SUGGESTION to a reviewer (trigram/edit distance with explicit threshold, token-set not raw substring); never auto-merge on fuzzy. Add Bengali-aware folding (Bengali digits to ASCII, ZWJ/ZWNJ strip, optional ি/ী, ু/ূ, য়, ণ/ন folding as a separate "loose key"), honorific stripping for authors ("ড.", "ডক্টর", "মো:"), an author alias table, and make "part/volume N" an explicit structured field so volume 1 never matches volume 10.
- Edition: compare publisher, edition and translator; group sibling editions under a work entity; allow a reviewer to say "new edition" from the submission screen and carry the group hint into persistence.
- Do not reject an author because of a heuristic; keep the raw string and a confidence flag. Missing author should produce NEEDS_REVIEW, not "new book".
- Deleted-book reuse: require author match or require reviewer action; never silently overwrite.
- Job semantics: separate "job finished" from "outcome" (created, linked_existing, duplicate_pending_review, needs_review, unresolved, failed).
- One pipeline for both manual submissions and catalog automation, with the same duplicate policy and the same operator actions (force, new, new_edition, confirm_duplicate, pause/resume).
- Notification: add an explicit event to the submitter (or at least a status endpoint/SSE) instead of poll-only; define what is stored in the submission record vs the book.
- Do the title-to-source resolution asynchronously in a worker, with bounded batch size per request and per-user quotas.

DROP
- `exec()`-concatenated modules; duplicated `get_with_host_fallback`; Celery revoke alongside Redis engine; inline-fallback processing inside HTTP requests; the vowel-stripped literal lists in `extract_core_title`/prefix stripping; manual UDP DNS and DoH with `verify=False`; fake browser User-Agent; the `legacy_scrape_overridden` test-detection by `__module__` (processing_job_runner.py:84-93); `classify_incoming_book` as dead code if not wired.
- Anything that ties the system to scraping a third-party site (source catalog crawl, host allow-list, `SOURCE_SITE_*`) unless the rebuild's ingestion still needs it (product decision, not mine).
